## What are Outcomes?

Every completed call or SMS conversation generates raw data: call length, transfer status, pathway tags, citations, and more. But to understand what actually happened, you usually need to combine multiple data points together.

Outcomes let you do exactly that. You define rules that connect post-call data (tags, citations, metadata) and produce a final result for each call or conversation. Outcomes work across both voice calls and SMS conversations.

### The Problem

After a call, you might have:

- **Pathway tags** like `"Appointment Confirmation"`, `"Objection Handling"`, `"Call Completion"`
- **Citations** with extracted variables like `firstName: "James"`, `appointmentConfirmed: true`
- **Call metadata** like `call_length`, `transferred_to`, `answered_by`, `call_ended_by`

No single data point tells the full story. A call tagged `"Appointment Confirmation"` where the customer said "no" isn't a confirmed appointment. A transferred call might look successful based on tags, but if the transfer duration was 0 seconds, the handoff probably failed.

### The Solution

Outcomes run transformation code against the full call context after post-call processing completes. You define outcome fields with a name, type, and description, and the platform generates the transformation code to extract what you need.

You can then attach outcomes to your post call webhooks, or just query the `GET /v1/calls/:id` endpoint to retrieve the outcomes for a specific call.

Each call or SMS conversation can have **multiple outcomes** attached through the `disposition_ids` field. One outcome might determine whether an appointment was booked while another classifies customer sentiment. Both run independently against the same data.

### Creating Outcomes

The easiest way to create outcomes is through the [Bland platform](https://app.bland.ai). For each outcome, you define fields with:

- **Field name** - The name of the value to extract (e.g., `appointmentBooked`, `callDisposition`)
- **Type** - The data type (e.g., `boolean`, `string`, `number`)
- **Description** - A plain-language description of what this field should capture

The platform generates the transformation code from your field definitions. No code required on your end. Describe what you want to know about each call and the platform handles the rest.

### Back Testing

After defining an outcome, you can back test it against production calls to verify the results before deploying to live traffic. This lets you iterate on your field definitions until the extracted values match what you expect.

Select **Run test** in the outcome editor and choose which calls to test:

- **Recent calls** - Test against your most recent production calls. Set a count and preview how many calls match before you run.
- **Specific calls** - Pick calls from your call log or paste conversation IDs directly.

The test runs your current draft against the selected calls. Results appear in a table with one row per call, and rows fill in as each call finishes.

#### Correcting Results

When a test run produces a wrong value, you can correct it directly in the results table. Each correction records the value you expected and a short rationale explaining why. A Corrections section above the results table summarizes every correction on the run, showing the original value, your corrected value, and your rationale.

#### Proposing Changes from Corrections

Once a finished test run has corrections, select **Align with AI** to have Bland propose changes to the outcome's definition based on them. For each corrected value, Bland reviews your corrections alongside the original results and suggests edits to the prompts and descriptions that produce that value.

Each proposal shows the current text, the suggested replacement, and the reasoning behind the change as a before/after diff. You choose which changes to keep, and you can add extra instructions and regenerate the proposals if the first pass misses the mark. Nothing is applied to your outcome until you apply it.

When you're ready, choose one of two actions:

- **Apply** - Saves the accepted changes to your outcome.
- **Apply and retest** - Saves the accepted changes, then reruns the test against the same calls. You land on a comparison of the new run against the corrected one, so you can see whether the changes helped.

A few things to know:

- Proposals are only generated for values you corrected in that run.
- Values powered by custom code are not changed by proposals.
- Proposals require the test run to be finished and to have at least one correction.
- If the outcome's definition changed after the proposals were generated, the affected proposals are disabled. Regenerate them to get proposals based on the current definition.

### Versioning

Every time you update an outcome's transformation code, a new version is created. Previous versions are preserved, so you can:

- **See which version ran on any given call** - Each call's outcome result is tagged with the version that produced it
- **View diffs between versions** - Compare what changed in the transformation code from one version to the next
- **Roll back if needed** - If a new version produces unexpected results, you can revert to a previous one

This makes it safe to iterate on your outcomes over time. You always have a clear audit trail of what logic ran on which calls, and you can trace any result back to the exact version of the transformation code that generated it.

## Use Cases

### Appointment Setting
Determine whether an appointment was booked, declined, or if the call dropped before reaching a conclusion by combining pathway tags with citation-extracted confirmation signals.

### Sales Qualification
Classify calls as "Qualified Lead", "Not Interested", "Callback Requested", or "Wrong Number" based on pathway progression, extracted customer responses, and call duration.

### Support Resolution
Identify whether an issue was resolved on the call, escalated via transfer, or left unresolved using transfer metadata, pathway tags, and cited customer statements.

### Compliance Verification
Confirm that required disclosures were made and acknowledged by checking that specific pathway nodes were visited and citation-extracted acknowledgments are present.

## Getting Started

To set up Outcomes for your enterprise account:

1. **Create an outcome** - In the [Bland platform](https://app.bland.ai), define your outcome fields with a name, type, and description
2. **Review the generated code** - The platform generates transformation code based on your field definitions
3. **Back test against historical data** - Verify the outcome produces correct results on real call or conversation data
4. **Attach to your calls or SMS conversations** - Add the outcome's ID to the `disposition_ids` field when [sending calls](/api-v1/post/calls) or [sending SMS](/api-v1/post/sms-send)

Reach out to your enterprise account manager or [contact our team](https://www.bland.ai/book-a-demo) to get Outcomes enabled and configured for your account.
