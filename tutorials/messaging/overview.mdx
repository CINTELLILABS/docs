# Introduction

Bland Messaging lets you run conversational agents over SMS, RCS, and iMessage from one place. The same pathways, personas, tools, memory, and analytics power every channel, so the flow you build for voice can drive your text conversations without rebuilding it.

<Info>
  **Plan availability.** Messaging is available on Enterprise plans and the [Agent Phone Plan](/platform/agent-phone-plan). The Agent Phone Plan includes SMS only. For Enterprise, contact your Account Executive or [reach out to sales](https://www.bland.ai/book-a-demo) to get set up.
</Info>

## Channels

Each channel has different reach and capabilities. You can use one number for one channel, or layer them so the same contact escalates to richer messaging when supported.

If your number is provisioned for RCS or iMessage, Bland uses the richest channel the recipient supports and falls back when needed.

## Attaching a pathway or persona

Pathways and personas attach to messaging numbers the same way they attach to phone numbers for calls. From the [Messaging dashboard](https://app.bland.ai/dashboard/sms), pick a number and configure it with a [pathway](/tutorials/pathways) or a [persona](/tutorials/personas). The number then handles inbound messages using the same logic, tools, and memory you use on voice.

If you already have a voice pathway, you can clone it for messaging and use the **Sync** action to keep both in sync as you iterate.

## Running a V2 agent

To run a V2 agent on a messaging number, attach the number to the agent in the dashboard ([Put an agent on a phone number](/agents/dispatch#put-an-agent-on-a-phone-number)) or with [Attach Numbers to Agent](/api-v2/post/agents-id-inbound-attach). Texts your customers send to the number, and conversations you start from it with the `/v1/sms/*` endpoints, then run the agent. These endpoints take no `agent_id`: the number decides which agent replies.

Keep these behaviors in mind when you move an integration from a pathway or persona:

- Don't pass `persona_id` on [Send SMS](/api-v1/post/sms-send) from an attached number. The send reassigns the number to that persona, for texts and calls, and the number stops running the agent.
- If your integration sends with a `pathway_id` you can't change yet, a [migration split](/platform/migrate-api-integrations) on that pathway can route new conversations started from Send SMS to the agent. See [V2 agents](/api-v1/post/sms-send#v2-agents) for when a split applies.
- Bland records the agent on a conversation when the conversation is created. A conversation that was already active when you attached the number keeps the V1 analysis and webhook shape.
- When the agent's Messages channel is turned off, for the agent or for a number, inbound texts to the number are stored but get no reply. Send SMS, Create SMS Conversation, and Send SMS Batch requests from the number fail with `403` and error code `CHANNEL_DISABLED`.

## Memory across conversations

[Memory](/tutorials/memories) can be enabled on any messaging channel and is shared with your voice agents. When memory is on, the same contact is recognized across SMS, RCS, iMessage, and voice, with one coherent history of facts, summaries, and open items. For example, an agent can remember how a customer wants a report formatted, then reuse that preference the next time the customer reaches out, regardless of which channel they use.

## Conversation lifecycle

When a conversation ends (via timeout, end-call node, or opt-out), the agent stops responding. Restart by deleting the conversation or its messages in the [messaging dashboard](https://app.bland.ai/dashboard/sms), then start a new thread.

Per-number and per-request settings let you control:

- **Timeouts.** When the user goes silent for a configured period, the agent can send a warning message and end the conversation.
- **Restart on reply.** When `restart_after_end_call` is enabled, a new conversation starts automatically if the user replies after the previous one ended.
- **Webhooks.** Each agent reply (and the conversation status) can be POSTed to a URL of your choice with the full message context.

## Outcomes, citations, and summaries

Messaging conversations support the same post-conversation analytics as voice. When a conversation ends, Bland can:

- Run [outcomes](/tutorials/outcomes) to classify what happened.
- Extract [citations](/enterprise-features/citations) from the transcript.
- Generate a summary using a custom prompt.

These can be configured per number on the messaging config, or passed per request on `/sms/send`. Webhook payloads include a `channel` field set to `"sms"`, `"rcs"`, `"whatsapp"`, or `"imessage"` so you can route them to the right handler.

When a conversation ends, the status webhook includes the full conversation context:

- `variables` (pathway variables collected during the conversation)
- `metadata` (custom metadata passed when the conversation was created)
- `pathway_tags` (tags from pathway nodes visited during the conversation)
- `concatenated_transcript` (the full conversation transcript as a single string)
- `summary` (AI-generated summary, when a summary prompt is configured)
- `citations` (extracted citation variables, when citation schemas are configured)
- `dispositions` (outcome run results, when outcomes are configured)

Message webhooks also include `variables`, `metadata`, `pathway_tags`, and `created_at` for parity with voice call webhooks.

### On a V2 agent conversation

A conversation that runs a V2 agent doesn't run outcomes or citation schemas, whether they're set on the number or passed on the request. Bland drops them without an error. The agent's [Dispositions](/agents/dispositions) run instead. A summary prompt on the number still runs.

The status webhook sent when an agent conversation ends carries `agent_id`, `agent_version_id`, and `agent_dispositions` in place of `citations` and `dispositions`. `agent_dispositions` can be an empty array. Dispositions set to **Hold original webhook** arrive in it. Other dispositions arrive later in a separate webhook to the same URL, with `event_type` set to `dispositions`, the `conversation_id`, and `agent_dispositions`. Message webhooks don't include the agent fields.
