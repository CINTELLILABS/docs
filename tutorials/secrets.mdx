---
title: "Secrets"
description: "Create, refresh, and reference credentials without exposing stored values."
---

Store API keys and access tokens as secrets, then reference them in tool requests instead of pasting credentials into prompts. Stored values cannot be viewed after saving.

## Open Secrets

Go to [Settings → Developer → Secrets](https://app.bland.ai/settings/secrets). The table shows each secret's **Key**, **Type**, reference, timestamps, and refresh status. Copy a reference from its row when you need to use it.

## Create a secret

Select **Create secret**, then **Static** or **Refresh**. Keys accept letters, numbers, and underscores.

### Static

Enter a key and value, then select **Create secret**. Use this for a credential that stays the same until you replace it.

### Refresh

Configure the request that fetches the credential:

- **Key**: the name used in references.
- **Refresh URL**: a complete HTTP or HTTPS URL. Put query parameters in the URL.
- **Method**: GET or POST. POST supports a JSON body.
- **Headers**: headers required by the service.
- **Refresh interval**: 10 to 1440 minutes.
- **Response path**: a JSONPath starting with `$` that selects the credential from the response.

Use **Test and extract** to check the request and choose the response value. You can save a refresh configuration without an initial value, but its reference will not have a credential until a successful refresh sets one. Check the interval against the token's lifetime.

## Reference a secret

Use the row's copy action to get the supported reference, or reference its key by name:

```text
{{secret.slack_token}}
```

Use references in webhook authorization, headers, and supported tool request fields. See [Tools](/agents/tools#store-credentials-as-secrets) for the distinction between name and ID references in tool requests. Keep secret values out of agent prompts.

## Edit, pause, or delete

**Edit secret** lets you rename a key, replace a static value, or change a refresh configuration. The stored value remains hidden. Leaving a static value untouched keeps it; typing a replacement updates it. When editing a refresh secret, keep the existing value or use a newly extracted value, and review any clear-value action before saving.

Pausing a refresh secret stops automatic refreshes and keeps its existing value available. Resume it when the request is ready again.

**Delete secret** permanently removes the stored value. Any use of its reference stops working. Renaming a key also breaks references that use its old name; update those references together.
