Alerts check your calls and notify you when a configured threshold is crossed. Define a condition, set severity levels, and choose where notifications go.

Configure alerts at the [Alerts dashboard](https://app.bland.ai/dashboard/alerts).

## How alerts work

Each alert is a configuration that combines three things:

1. **A condition**: what to measure on each call (a built-in metric or a custom signal).
2. **One or more severity levels**: INFO, WARNING, and CRITICAL, each with its own threshold and percentage trigger, using the alert's time window.
3. **A delivery target**: email, phone call, or a custom tool to notify when a level triggers.

The platform checks completed calls against the alert's condition, then checks whether the percentage of flagged calls within the time window crosses a level's threshold. If it does, the alert becomes **Triggered** and your notifications go out.

## Conditions

### Built-in metrics

Two metrics are available on every plan:

- **Call length**: total duration of the call.
- **API errors**: calls where an API hit returned a non-2xx status or timed out.

Enterprise plans unlock advanced metrics:

- **Latency**: average response latency.
- **Transcription score**: speech-to-text confidence.
- **Silence count**: long pauses where neither party is speaking.
- **Sentiment score**: how the contact reacted during the call.
- **Low engagement ratio**: share of the call where the contact gave very short responses.
- **User interruption count**: how often the contact interrupted the agent.

### Custom conditions

Custom conditions use structured signals you already produce. Select a source and compare its value:

- **Citation variables**: values extracted by a [citation schema](/enterprise-features/citations) (e.g. `appointmentConfirmed: true`).
- **Disposition fields**: results from an [outcome](/tutorials/outcomes) (e.g. `disposition.qualified === false`).
- **Pathway tags**: whether a specific tag was hit on the call.

This lets you alert on business outcomes, not just system metrics.

Legacy custom conditions written in plain language have been disabled and cannot be re-enabled. Create a replacement using one of these structured sources.

## Severity levels

Every alert supports up to three levels:

| Level    | Use it for                                            |
| -------- | ----------------------------------------------------- |
| INFO     | Heads-up signals you want to track but don't page on. |
| WARNING  | Trending issues worth investigating soon.             |
| CRITICAL | Active problems that need immediate attention.        |

Each level has its own:

- **Operator and value**: e.g. `call_length > 600s`.
- **Percentage trigger**: the share of calls in the time window that must be flagged before the level triggers (for example, more than 10% of calls exceed the threshold).

**Time window** sets how far back the alert looks at calls. Options are 10 minutes, 30 minutes, 1 hour, 3 hours, or 24 hours.

The percentage trigger controls how many calls must be flagged before an alert triggers. A single flagged call can cross the threshold when call volume is low.

Set **Minimum calls** to require a minimum number of calls in the time window before the alert can trigger. Set it to 0 for no minimum.

## Notifications

When a level triggers, the platform delivers a notification to any of the following:

- **Email**: one or more email addresses.
- **Phone call**: an outbound voice call to a list of numbers, with a custom spoken message.
- **Custom tool**: invoke one of your [custom tools](/tutorials/v2-tools) with an input payload. Useful for routing to Slack, PagerDuty, a webhook, or anything else you've already wired up.

You can mix and match. The same alert can email a team alias _and_ trigger a Slack tool.

## Alert lifecycle

An alert config has two pieces of state visible in the dashboard:

- **Status**: **Enabled** (checking calls) or **Disabled** (paused). Toggle this without deleting the alert, except for disabled legacy plain-language custom conditions.
- **State**: **Not triggered** if no level is currently triggered, or **Triggered** with a severity badge if one is. **Last triggered** and **Last saved** show when the alert last triggered and when its configuration was saved.

When a triggered alert recovers (the percentage drops back below all thresholds), the state returns to **Not triggered**. The history is preserved so you can review past incidents.
