## What Are Tools?

When your AI phone agent talks to a caller, it can do more than have a conversation. It can take real actions during the call:

- Schedule a meeting on Cal.com when a caller wants to book time
- Create a contact in Salesforce when someone provides their info
- Send a Slack message to notify your team about an interested lead
- Call your own API to check order status or update a database

These actions are called **tools**. A tool is something your agent can do when the conversation calls for it.

---

## Tools vs Custom Tools (Legacy)

If you've used Bland before, you may have used **Custom Tools** (now legacy). Here's how they compare:

| Feature | Custom Tools (Legacy) | Tools |
|---------|-------------------|----------|
| Configuration | Raw JSON, manual HTTP setup | Visual Tool Builder |
| Integrations | Build everything yourself | Pre-built integrations + custom API |
| Authentication | Manual header configuration | Managed OAuth and API keys |
| Field Input | Static values only | Agent Mode, Linked Mode, Manual Mode |
| Response Handling | Manual parsing | Visual response variable extraction |
| Pathway Variables | Not supported | Link variables to tool inputs |
| Tool Logs | None | Execution logs per tool |

## How Tools Work

Every tool has four sections:

**1. Integration Configuration:** Which connection and action to use (Salesforce → Create Contact, API → POST, etc.)

**2. Prompting:** When the AI should use this tool and what it says during execution

**3. Action Parameters:** The data the tool needs (fields, values, how to get them)

**4. Response Variables:** What to capture from the result and how to use it

You create a connection once, then build multiple tools using that connection. For example:

**One Salesforce connection** could power:
- A "Create Contact" tool
- A "Create Lead" tool
- A "Create Opportunity" tool

**One API connection** to your backend could power:
- A "Check Order Status" tool
- A "Update Customer Record" tool
- A "Submit Support Ticket" tool

## Creating a Tool

**Set Up a Connection:** Connect to the service your tool will use. For third party integrations, sign in with OAuth. For custom APIs, configure your endpoint and authentication. You only do this once per service.

**Choose an Action:** Each connection offers specific actions. Cal.com has Schedule Meeting and Get Available Times. Salesforce has Create Contact, Create Lead, Create Opportunity. Your API connection has GET and POST to any endpoint.

**Configure the Tool:** The Tool Builder has four sections. Integration Configuration selects your connection and action. Prompting tells the AI when to use the tool and what to say. Action Parameters define what data the tool needs. Response Variables capture data from the result.

**Add to Pathway:** Use the tool in your conversational pathway. Route based on results: success goes one way, errors another.

**Walkthroughs:**
- [Integration Tools](/tutorials/tools/integration-tools): Cal.com, Salesforce, Slack, and others
- [Custom API Integration](/tutorials/tools/custom-api): Your own endpoints and custom APIs

## Tools with Personas

When you add a tool to a Persona, the agent decides when to use it and fills in the parameters automatically.

### How It Works

1. Add your tool to the Persona's tool list
2. The agent reads the tool's prompt to know when to use it
3. When triggered, the agent fills Agent Mode fields from the conversation
4. Linked Mode fields use system variables automatically
5. Manual Mode fields use the static values you set

![Persona Tool List](/tutorials/tutorials-assets/v2-tools/personas-tool-list.png)

### Tool Prompts

The tool's **prompt** tells the agent when to use it. Be specific:

**Good prompt:**
```
Use this tool when the caller wants to schedule a demo call
and has confirmed they're available next week.
Don't use for general questions about the product.
```

**Bad prompt:**
```
Schedule meetings
```

### Parameter Modes in Personas

Every tool field needs a value. Where does that value come from? That's what parameter modes solve.

**Agent Mode:** The field is for the AI agent to fill in based on the call conversation.

During the call, the agent listens to what the caller says and extracts the value when the tool is used. This is for information the caller provides that you couldn't know ahead of time.

*Use Agent Mode when:*
- The caller provides their name, email, or phone number
- The caller mentions their preferences or requirements
- The caller describes a problem or request
- Any information that comes from what the caller says

*Don't use Agent Mode when:*
- You already know the value (use Manual Mode instead)
- The system already has the value (use Linked Mode instead)

Example: The caller says "my email is john@example.com" and the agent captures "john@example.com" from the conversation and uses it in the tool.

![Agent Mode in Personas](/tutorials/tutorials-assets/v2-tools/agent_mode_slack_example.png)

**Manual Mode:** You know the value ahead of time. It never changes.

Use this for fixed values that are the same for every call.

Example: Always book on the "Sales Demos" calendar. Always set the lead source to "phone_call".

![Manual Mode in Personas](/tutorials/tutorials-assets/v2-tools/static_input_mode.png)

**Linked Mode:** The system already knows this value. No need to ask or configure.

Use this for system variables that are automatically available.

Example: `{{from}}` is the caller's phone number, which is already available. `{{call_id}}` is the unique identifier for this call.

![Linked Mode in Personas](/tutorials/tutorials-assets/v2-tools/linked_mode_SMS_example_link_phonenumber.png)

**Important:** In Pathways, Agent Mode works differently. You add tools using the **Custom Tool node**, and the agent doesn't fill these fields automatically. Instead, you use Variable Extraction in earlier nodes and link to those variables in the Custom Tool node's Fields section. See the Tools with Pathways section below.

## Tools with Pathways

In Pathways, you control when tools run and how parameters are filled. The agent doesn't fill fields automatically: you link them to pathway variables.

### How It Works

1. Extract variables in earlier nodes using Variable Extraction (caller name, email, etc.)
2. Add a Custom Tool node to your pathway
3. In the Fields section, select which pathway variables to use for each tool input
4. The tool runs when the pathway reaches that node

![Custom Tool Modal](/tutorials/tutorials-assets/v2-tools/custom_tool_modal.png)

### Parameter Mapping in Pathways

In Pathways, the tool doesn't run on its own. You control exactly when it fires and what data it uses.

**Manual Mode:** Same as Personas. Fixed value you set in advance.

![Parameter Mapping in Pathways](/tutorials/tutorials-assets/v2-tools/pathway_parameter_mapping.png)

**Agent Mode fields:** Here's the key difference. The agent doesn't fill these automatically during the call. Instead, you extract variables earlier in your pathway and link them in the Custom Tool node's Fields section.
Example: You extracted `customer_email` in a previous node. Now you select it for the email field.

**Linked Mode:** System variables like the caller's phone number and call ID are available automatically.

### Example

1. Earlier node extracts `customer_email` and `customer_name` using Variable Extraction
2. Custom Tool node Fields section:
   - email → select `customer_email`
   - name → select `customer_name`
3. Tool executes with those values

![Pathway Example with Tool](/tutorials/tutorials-assets/v2-tools/custom_tool_pathway_example_with_slack.jpeg)

### Response Routing

Route your pathway based on tool results:

| If | Condition | Then Go To |
|----|-----------|------------|
| `ok` | equals `true` | Confirmation Node |
| `ok` | equals `false` | Error Handler |

Available conditions: `==`, `!=`, `>`, `<`, `contains`, `is null`, `is not null`

## Response Variables

When a tool runs, it returns data you can use in your conversation or pass to other tools.

**Why response variables exist:** After booking a meeting, you might want to tell the caller the confirmation number. After creating a contact, you might want to confirm their record was saved. Response variables let you capture this data and use it.

### Response Modes

**Capture Response:** The tool waits for a response and captures the data. Use this when you need to check if the request succeeded, get data back (like a confirmation number), or route your pathway based on the result.

**Fire and Forget:** The tool sends the request but doesn't wait for a response. Use this when you don't need confirmation, speed is critical, or the action is fire-and-forget (like logging or notifications).

![Response Modes](/tutorials/tutorials-assets/v2-tools/response_modes.jpeg)

![Response Variables](/tutorials/tutorials-assets/v2-tools/pathway_tool_response_variables.png)

### What you get back (Capture Response)

- Whether the tool succeeded or failed
- A status message
- The actual data from the service (contact ID, booking URL, etc.)

**How to use them:**
- In the Tool Builder, you define which fields to capture
- Use `{{variable_name}}` syntax to reference captured data
- Route your pathway based on success or failure

## Filling silence during long tool calls

When a tool takes several seconds to respond, the caller can otherwise sit in silence with no way to interrupt. `tool_assist` is an optional per-tool setting that keeps the call feeling natural while the tool runs in the background.

You can combine three behaviors:

- **Nudges** — timed reassurance lines the agent speaks while the tool is still running (for example, "still on it, one moment").
- **Aside** — lets the caller speak and get a short conversational reply while the tool finishes in the background. The agent wraps up the chat and delivers the tool result once it returns.
- **Stream updates** — for endpoints that stream a response, partial progress is fed into the agent's context so nudges and asides can reference what's happening ("the system says step 2 of 3 is done").

`tool_assist` is opt-in per tool. When it's not set, the tool keeps the current behavior of playing at most one filler line during execution.

You can also give the tool an **immediate filler line** the agent speaks the moment the tool starts (for example, "Let me look that up for you."). This is the same idea as the tool's existing speech line, exposed alongside the newer controls.

### When to use it

- Set an **immediate filler line** on any tool where you want the agent to acknowledge the request the moment it fires.
- Reach for **nudges** on tools that regularly take more than a few seconds. Timed reassurance is less jarring than silence.
- Enable **aside** when callers commonly try to talk mid-wait — for example, adding a detail they forgot or asking a related question — and you want the agent to respond instead of ignoring them.
- Enable **stream updates** only when your endpoint streams incremental progress. Non-streaming tools don't benefit from it.

### Configuring from the pathway editor

Open a tool on a pathway node and scroll to the **While the tool runs** section. From there you can:

- Set the immediate filler line the agent speaks when the tool starts.
- Add up to five timed nudges. Each nudge has a delay (between 0.25 and 55 seconds from tool start) and is either static text or a short prompt the agent uses to compose a line in the moment. Three rows are seeded at 2, 8, and 15 seconds — remove or edit them freely.
- Toggle the aside and give it a steering prompt.
- Toggle streamed progress for endpoints that stream their response.

Assist settings are saved on the tool only when enabled, so existing tools are left untouched until you opt in.

### Configuring from the API

`tool_assist` is a field on the tool's configuration inside a pathway node:

```json
{
  "tool_assist": {
    "enabled": true,
    "nudges": [
      { "delay_ms": 2000, "text": "Just a moment while I pull that up." },
      { "delay_ms": 8000, "prompt": "Reassure the caller you're still working on their request." },
      { "delay_ms": 15000, "text": "Almost done, thanks for your patience." }
    ],
    "aside": {
      "enabled": true,
      "prompt": "Keep the caller company briefly. Stay on topic and don't promise anything until the result comes back."
    },
    "stream_updates": {
      "enabled": true,
      "max_updates": 10
    }
  }
}
```

**Nudges**

Each nudge has a `delay_ms` (measured from when the tool starts) and either:

- `text` — a fixed line the agent speaks verbatim, or
- `prompt` — a short instruction the agent uses to compose a one-liner in the moment.

If both are set, `text` wins. Nudges are skipped whenever the caller or agent is already speaking, so they never cut anyone off. A nudge that would land after the tool has already returned is dropped.

**Aside**

When `aside.enabled` is `true`, the caller can interrupt during the tool window and the agent responds in a short side conversation, steered by `aside.prompt`. Tools are disabled during the aside so the agent won't start a second tool call. Once the original tool result arrives, the agent finishes the side thread and delivers the result.

**Stream updates**

For streaming endpoints, partial output is added to the agent's context up to `max_updates` chunks (default 10). Nudges and aside replies that come after each chunk can reference the latest progress.

## Monitoring

Tools give you full visibility into what's happening during calls.

## API Reference

Manage tools programmatically using the Tools API:

- **[Create Tool](/api-v2/post/tools):** Create a new integration tool connected to Slack, a custom API, or any supported integration.
- **[List Tools](/api-v2/get/tools):** Retrieve a paginated list of your tools.
- **[Update Tool](/api-v2/post/tools-tool-id):** Update any field on an existing tool. All fields are optional.
- **[Tool Execution Logs](/api-v2/get/tools-logs):** Query per-execution logs across your tools.
- **[Execution Stats](/api-v2/get/tools-logs-stats):** Aggregate execution metrics grouped by integration, status, date, and more.
