A GitHub workspace keeps an agent's source in a private GitHub repository. You can edit the agent in the dashboard, in Git, or with a coding agent such as Claude Code, Codex, or Cursor. Bland keeps both sides in sync.

Use a GitHub workspace when you want code review, pull requests, and Git history for agent changes, or when you edit agents locally with a coding agent.

Git never changes live traffic. Merging a pull request updates source only. You still publish and promote from Bland, as described in [Environments](/agents/environments).

<Note>
GitHub workspaces are rolling out gradually. If your agent doesn't show a **GitHub** button, the feature isn't enabled for your organization yet.
</Note>

## Prerequisites

- An agent, from [Agent builder](/agents/agent-builder)
- An owner or admin role in your Bland organization
- A GitHub account where you can install the Bland GitHub App
- For local validation: Node.js 22 or newer

## What the repository contains

When Bland creates the repository, it adds:

| File or folder | What it holds |
|----------------|---------------|
| `bland.json` | The agent's native JSON source, including custom code with versioned snippets, plus its evaluations and test cases |
| `scripts/validate.cjs` | An offline validator for the source |
| `AGENTS.md` and `CLAUDE.md` | Instructions that tell coding agents how to edit and test this agent safely |
| `.bland/norm` | Bundled [Norm](/integrations/mcp/norm) authoring skills, plus a workspace skill that Codex and Cursor discover |
| `README.md` | A short guide to the workspace |

The repository references voices, knowledge bases, tools, and snippets in your Bland account. It doesn't copy credentials, contact memory, or call history. Keep API keys and real customer data out of Git.

Bland writes the instructions, skills, and validator once, when it creates the repository. Later syncs don't upgrade them.

## Connect a repository

Open the agent and select **GitHub** at the top right, next to **Publish**.

<Tabs>
  <Tab title="Create a new repository">
    1. Select **Create repository**. A GitHub tab opens.
    2. On GitHub, install or authorize the Bland GitHub App. Choose **Only select repositories** to limit access. For your first installation, GitHub asks you to select at least one existing repository.
    3. Approve access. Bland creates a separate private repository for this agent in your account and connects it. You can close the panel while setup runs.

    **All repositories** grants Bland access to every current and future repository in that account.
  </Tab>
  <Tab title="Use an existing repository">
    1. Select **Use an existing repository**, then **Authorize GitHub**.
    2. On GitHub, choose **Only select repositories** and select the repository you want to connect.
    3. Back in Bland, choose the repository and select **Connect repository**.

    One repository connects to one agent. If the repository already belongs to another agent, disconnect it there first.

    If the repository and the agent contain different source, Bland asks which side to keep:

    - **Replace this agent with GitHub** replaces the agent's current draft and evaluations with the repository's source.
    - **Replace GitHub source with this agent** replaces the repository's managed source at the next sync.

    Saved versions and Git history are kept either way. Running deployments don't change.
  </Tab>
</Tabs>

Once connected, the GitHub panel shows the repository name, the branch you're viewing, and its sync status. Select **Open in GitHub** to go to the repository.

## How branches map to environments

| Git branch | Bland |
|------------|-------|
| `dev/main` | The agent's default development draft |
| `dev/<branch-name>` | A named development draft |
| `staging` | Staging source |
| `main` | Production source |

To see the branches for your agent, open the GitHub panel and select the settings icon. **Connected branches** lists the branch for Development, Staging, and Production.

If you're on a development draft that isn't tracked yet, select **Sync this branch** in the GitHub panel.

<Warning>
`main` and `staging` hold source, not what is live. A merge into `main` doesn't change the version that answers calls. Production keeps its pinned version until you publish and promote from Bland.
</Warning>

## How changes sync

When you save in the dashboard, Bland pushes the change to the matching branch. When you push to a tracked branch, Bland imports it into the matching draft. Collaborators who have the agent open see the incoming change.

The GitHub panel shows the current state, such as **Synced**, **Saved. Syncing to GitHub…**, or **Importing GitHub changes…**.

When edits on both sides conflict, Bland doesn't overwrite either one:

- If Bland can't merge the edits, it saves your changes on a recovery branch. Select **Open recovery branch** to review it, or **Continue on recovery branch** to keep editing there.
- If a change needs review before it lands, Bland opens a pull request. Select **Open pull request** to review it. If the pull request is closed, select **Propose saved changes** to open a new one.
- If sync stops, select **Retry sync**. Your saved edits stay in Bland while sync is paused.

## Validate changes

### Locally

Run the validator from the repository root after you edit `bland.json`:

```bash
node scripts/validate.cjs
```

The validator runs offline and is free. It needs no package install or Bland login. It checks the source structure and graph references, such as routes that point to steps that don't exist. It doesn't run your agent's code or test its behavior.

Local validation gives you fast feedback. It doesn't replace the check Bland runs on pull requests.

### On pull requests

Bland runs a check on every pull request through the Bland GitHub App. The check validates the exact result of the merge against your Bland account, including the resources the agent references.

Open pull requests from branches in the same repository. Bland can't validate pull requests from forks.

Whether a failing check blocks the merge depends on your GitHub plan:

| GitHub plan | Merge protection |
|-------------|------------------|
| GitHub Pro (personal accounts), Team, or Enterprise | Bland adds a rule that requires a pull request and a passing check before merging into `main` |
| GitHub Free (private repositories) | Checks run but are advisory, so GitHub can merge source that fails |

**Merge protection** in the repository settings shows **Configured**, **Advisory**, or **Pending setup**. If it shows **Pending setup**, restore access in the Bland GitHub App and select **Retry setup**.

With advisory checks, Bland still rejects invalid source. The GitHub panel shows **Source validation failed**, and Bland keeps its last accepted version. Live traffic doesn't change. Fix the branch in GitHub, then select **Retry after correction**.

## Test and publish

Git pushes don't run paid tests. To run your agent's evaluations against the branch, open the repository settings and select **Run checks (uses credits)**. Results appear in the agent's check history. See [Evaluations](/agents/evaluations) to set up the judges and test cases these checks run.

To ship a change, use the buttons in the agent's top bar:

- On Development, select **Publish to staging**.
- On Staging, select **Promote to production**.

When the GitHub panel shows **New changes are ready to publish**, the branch has source that isn't live yet. Your live version stays the same until you publish.

## Edit locally with a coding agent

The GitHub panel includes a setup prompt for Claude Code. Select **Copy setup prompt** and paste it into Claude Code to clone the repository or open your existing copy.

Coding agents read `AGENTS.md` for the agent's identity and Git workflow. Codex and Cursor also load the bundled workspace skill. If you already have Norm installed, the repository reuses it and doesn't install a second copy.

To run simulations from your editor, connect Bland to it with access to the same organization. See [Connect Norm](/integrations/mcp/norm).

## Disconnect a repository

Open the repository settings and select **Disconnect repository**, then confirm.

Disconnecting stops sync for every branch of the agent. Bland keeps your agent, its deployments, and the GitHub repository, along with sync and evaluation history. Saved Bland changes that haven't synced yet aren't sent to GitHub. You can reconnect later.

## Common failures

<AccordionGroup>
  <Accordion title="Merged into main, but calls still use the old version">
    Merging updates source only. Publish to staging and promote to production from Bland. See [Environments](/agents/environments).
  </Accordion>

  <Accordion title="Source validation failed">
    The branch has source that Bland can't accept. Bland keeps its last accepted version. Fix the branch in GitHub, run `node scripts/validate.cjs` locally, push, then select **Retry after correction**.
  </Accordion>

  <Accordion title="GitHub access needs attention">
    The Bland GitHub App lost access to the repository. Restore access in the app's settings on GitHub, then retry sync.
  </Accordion>

  <Accordion title="No repositories are available">
    The Bland GitHub App has no access to the repository you want. Select **Manage GitHub access** and add the repository on GitHub.
  </Accordion>
</AccordionGroup>
