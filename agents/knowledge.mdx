Knowledge is how an agent answers from your content rather than from what it was told in a prompt. You add a source, attach it to an agent, and the agent searches it during the call when a caller asks something it covers.

A source is one thing you added: a file, a site, a block of text, a synced document. The product calls it a source everywhere, so this page does too.

The examples here build knowledge for a front desk agent at Northwind Dental, a fictional practice.

## Prerequisites

- An agent to attach sources to, from [Agent builder](/agents/agent-builder)
- The content you want the agent to answer from

## Where knowledge lives

**Knowledge** appears at two scopes, and the difference is what is attached rather than what exists.

The selector at the top of the sidebar decides which one you are on. It reads **All agents** for the whole organization, or the agent's name when you are inside one.

Both scopes show the same five tabs.

| Tab | What it is for |
|---|---|
| **Sources** | Everything you have added. At an agent, also where you attach. |
| **Questions** | Questions callers asked that the agent could not answer. |
| **Query logs** | Every retrieval, what it searched, and what came back. |
| **Knowledge map** | A picture of which sources are carrying the questions. |
| **Source testing** | Ask a question and see what the agent would retrieve. |

Sources themselves belong to the organization, never to one agent. The list is the same at both scopes. What changes inside an agent is that each row gains a checkbox, and the other four tabs narrow to the sources that agent has attached.

## Add a source

**Add sources** opens a dialog with four kinds along the top.

### Upload

Drag files in, or click to pick them. PDF, TXT, CSV, JSON and DOCX, up to 10 MB each and 10 files at a time.

Each file becomes its own source. Drop five files and you get five sources, not one with five parts.

A file over the limit is skipped and the rest still upload, with a message naming the one that did not make it.

### Website

Two ways to get URLs in. **Discover from a site** takes a domain, reads its sitemap, and comes back with everything it found, all selected. Turn off what you do not want and add the rest. Or paste URLs into the field below it, one or many at once, separated by spaces or commas.

The whole list becomes one source, so name it for the site rather than for a page.

### Text

Paste content directly, up to one million characters. This one needs a name.

Use it for the things that live nowhere else yet: a policy someone wrote in a message, a price list, the answers your team keeps retyping.

### Integration

Pick a document from an app you have connected, currently Notion or Google Docs. Bland reads it and keeps reading it.

An integration source is read-only in Bland. Edit the document where it lives, then re-sync.

<Warning>
Fill in **Description**, even though it says optional.

At call time the agent sees each attached source as a tool it can choose to use, and your description is what it reads when deciding. "Insurance, billing and payment plan policies" gets consulted. An empty description leaves the agent guessing.

This is the single cheapest thing you can do to make retrieval work.
</Warning>

Whichever kind you pick, the source starts processing in the background. It is not searchable until it finishes, and the **Status** column tells you where it is.

## Attach a source to an agent

Adding a source does not give it to an agent. Attach it.

<Steps>
  <Step title="Open the agent's Knowledge page">
    Switch the sidebar selector to the agent, then open **Knowledge**. You get the same source list with a checkbox on every row.
  </Step>

  <Step title="Check the sources it should use">
    The header counts them as you go.
  </Step>

  <Step title="Press Save">
    Nothing is attached until you do. The checkboxes are an edit to the agent, like any other, and they ship when the agent does.
  </Step>
</Steps>

An attached source is available on every call, everywhere in the agent, including inside every scenario. There is no per prompt version of this.

### Tagging, and how it relates

You can also type `@` in the agent's prompt and pick a source by name. That attaches it too, and it shows up checked the next time you look at the Sources tab.

Tagging is worth doing on top of attaching, because it tells the agent where in the conversation you expect the source to matter. It is not what makes the source reachable.

<Note>
This is the opposite of how [tools](/agents/tools) work. A tool is only available where you tagged it. A source is available once it is attached, tagged or not.

If you remember one difference between the two, make it this one.
</Note>

<Warning>
Untagging can detach, but only a source you attached by tagging.

Remove the last `@` mention of a source you never checked on the Sources tab and it is detached. A source you checked on the Sources tab stays attached no matter what you do to the prompt.
</Warning>

## Test what it retrieves

**Source testing** is where you find out what the agent would actually do with a question, before a caller asks it.

Pick your sources in the bar at the bottom, type a question, and press Enter. Inside an agent the picker starts with everything that agent has attached, so you are testing the real set.

The answer comes back with **Show diagnostics** underneath it, and the diagnostics are the point.

| What it shows | Why you care |
|---|---|
| **Generated query** | What it actually searched for, which is rarely word for word what you typed. |
| **Gap evaluation** | `answerable` or `gap`, plus the reason. |
| **Retrieved chunks** | The passages it found, each with a score, best first. |

A low score on the top chunk means the wording in your source and the wording of the question are too far apart. A good chunk that produced a bad answer is a different problem, usually a source that says two things at once.

<Note>
The diagnostics show which passages came back, not which source they came from. With several sources selected you cannot tell which one answered.

To pin it down, clear the picker and test one source at a time.
</Note>

When the tester decides a question is a gap, a banner offers to answer it on the spot. The answer is written into a source you pick, so the next caller who asks gets it.

## Edit a source

Open a source from the list. What you get depends on what it is.

| Source | Editor |
|---|---|
| Text and Markdown | One editor, full width |
| PDF and DOCX | The original on the left, the text Bland extracted on the right |
| JSON | The same split, for sources converted to Markdown. Older JSON sources open as plain JSON |
| CSV | A grid |
| Website | The URL list, plus **Sync now** and a daily auto-sync switch |
| Integration | Read-only, with a link out to the app it syncs from |

Saving is two steps. **Save** shows you a diff of what changed, and you commit from there. Content has to stay under 10 MB.

<Warning>
On a PDF, DOCX or JSON source you are editing extracted text, not the file.

Bland asks you to confirm, because after you save, the text your agent searches no longer matches the document a person would open. That is often what you want, for fixing a bad table or a garbled heading. It is worth knowing you are doing it.
</Warning>

Every content save creates a version. Past versions are read-only, and restoring one writes it forward as a new version rather than rewinding, so nothing is lost either way. Renaming a source and changing its retrieval settings do not create versions.

### Retrieval settings

CSV, JSON and website sources have a **Retrieval settings** button that does one job: tell retrieval which parts of the source carry the meaning.

On a CSV you boost up to three columns and exclude the ones that are noise, like IDs and URLs. On JSON it is the same idea with paths. On a website source it is one switch, for using each page's title and description.

Everything here starts off. **Suggest** fills it in for you on CSV and JSON, and explains its reasoning. Saving reindexes the source.

Leave it alone unless retrieval is missing things it obviously should find. It is a fix for a specific problem, not a setup step.

## Manage at scale

Three tabs matter once you have real traffic.

**Questions** collects what callers asked and the agent could not answer, mined out of live conversations, with how many times each one came up. Answer one and the answer is written into a source you choose. Dismiss the ones that are not your job. The list opens on **Open** and sorts by how often each was asked, so the top of it is your work queue.

**Query logs** is every retrieval: the query, whether it was answered, where it came from, and the chunks that came back. Open a row for the full picture. The default window is the last 7 days.

**Knowledge map** draws your sources against the questions raised against them over 30 days, colored by how often they answered. Red is a source that is being asked and failing. Grey is a source nothing has asked in a month.

<Note>
Inside an agent, **Query logs** only shows calls made since agent attribution shipped. Older traffic is still there, on the same tab at **All agents**.
</Note>

Everything on the Sources table is a rolling 30-day window: queries, share, hits, misses, coverage. The list opens sorted by least coverage, so your weakest sources are on top.

## Common failures

<AccordionGroup>
  <Accordion title="The agent answers as though the source does not exist">
    Check the agent's Sources tab. If the row is unchecked, it is not attached. If it is checked and you never pressed **Save**, it is still not attached.
  </Accordion>

  <Accordion title="It is attached and still never gets used">
    Read the description you gave the source. The agent chooses whether to search it from that line alone. Rewrite it to say what the source covers, in the words a caller would use.
  </Accordion>

  <Accordion title="It retrieves the wrong passage">
    Test the question and look at the top chunk's score. A low score means your source and the question do not share vocabulary, which is a content fix. A good score on the wrong passage usually means one source is covering two topics, which is a splitting fix.
  </Accordion>

  <Accordion title="A source sits on Processing">
    Large files take a while, and the row shows a percentage and an estimate. A source that has gone to **Failed** shows why on hover.
  </Accordion>

  <Accordion title="The site source is out of date">
    Open it and use **Sync now**, or turn on the daily auto-sync. A source marked **Stale** is one with auto-sync on that has not synced in more than 7 days.
  </Accordion>

  <Accordion title="The answer was right last week and is wrong now">
    Open the source and check its version history. Every content save made a version, and you can read what changed.
  </Accordion>
</AccordionGroup>
