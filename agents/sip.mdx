SIP lets you bring your own carrier. Calls from your carrier, PBX, or contact center reach a Bland agent, and the agent places calls out through your SIP provider.

You create a trunk, attach your numbers to it, and assign each number an agent.

<Note>
**SIP is organization scope only.** Inside a single agent there is no Phone numbers item. Switch the selector at the top of the sidebar to **All agents** first.
</Note>

## Where SIP lives

At **All agents**, go to **Dispatch**, then **Phone numbers**, then the **SIP** tab. It lists your trunks, and **Create trunk** and **Port a number** sit at the top right.

Each trunk has its own page with three tabs:

- **Overview**: call volume, answer rate, and the call log with each call's SIP trace
- **Numbers**: the numbers and DIDs attached to the trunk
- **Configure**: the trunk's endpoint, authentication, headers, and firewall details

## How it works

- A **trunk** holds the connection to your SIP infrastructure: the endpoint, transport, and authentication. You set it up once.
- **Numbers and DIDs** attach to a trunk and inherit its settings. Each one can route inbound, outbound, or both. E.164 numbers, DIDs, and extensions are all supported.
- **SIP headers become variables.** Every `X-` header your PBX sends reaches the agent as `{{sip_header_<name>}}`, and Bland can send call data back in headers. See [SIP headers](/agents/sip-headers).
- **Signaling runs over TLS on port 5061, and audio over SRTP.** Bland does not accept plain UDP or port 5060.

## Prerequisites

- A carrier, PBX, or SBC that supports TLS signaling and SRTP media
- The numbers you will route, on your own carrier. Numbers bought from Bland can't be attached to a trunk
- Access to your firewall, to allow-list Bland's [signaling and media IPs](/agents/sip-network#connection-endpoints)

## Connect your carrier

<Steps>
  <Step title="Create a trunk">
    On the **SIP** tab, press **Create trunk** and follow the [setup wizard](/agents/sip-setup). For Bandwidth, Twilio, Telnyx, 3CX, Five9, or NICE CXone, follow that provider's guide under **SIP integrations** in the sidebar instead.
  </Step>

  <Step title="Attach your numbers">
    Add the numbers or DIDs that route through the trunk, on the wizard's last step or the trunk's **Numbers** tab.
  </Step>

  <Step title="Assign an agent">
    Under **Phone numbers**, press **Configure** on the number and pick the agent under **Assignment**.
  </Step>

  <Step title="Place a test call">
    Call the number from a phone to test inbound. For outbound, use the number as `from`:

    ```bash
    curl -X POST https://api.bland.ai/v1/calls \
      -H "Authorization: Bearer <token>" \
      -H "Content-Type: application/json" \
      -d '{
        "phone_number": "+14155550123",
        "from": "+12341234123",
        "task": "Say hi to the nice person!"
      }'
    ```
  </Step>
</Steps>

You know it worked when the call shows up on the trunk's **Overview** tab.

## API

Every SIP endpoint is under `/v1/sip` and authenticates with your API key. Parameters for each endpoint are in the [API reference](/api-v1/post/sip-attach).

<AccordionGroup>
  <Accordion title="Trunks">
    | Method | Endpoint | Description |
    |---|---|---|
    | `POST` | `/v1/sip/trunks` | Create a trunk |
    | `GET` | `/v1/sip/trunks` | List trunks |
    | `GET` | `/v1/sip/trunks/:id` | Get a trunk and its attached numbers |
    | `PATCH` | `/v1/sip/trunks/:id` | Update a trunk |
    | `DELETE` | `/v1/sip/trunks/:id` | Delete a trunk |
    | `POST` | `/v1/sip/trunks/:id/test-connection` | Send a SIP OPTIONS reachability ping |
  </Accordion>

  <Accordion title="Numbers and configuration">
    | Method | Endpoint | Description |
    |---|---|---|
    | `GET` | [`/v1/sip`](/api-v1/get/sip-config) | Get SIP config for a phone number |
    | `POST` | [`/v1/sip/attach`](/api-v1/post/sip-attach) | Attach numbers and DIDs to a trunk |
    | `POST` | [`/v1/sip/update`](/api-v1/post/sip-update) | Update one direction's settings |
    | `POST` | [`/v1/sip/detach`](/api-v1/post/sip-detach) | Remove SIP configuration |
    | `GET` | [`/v1/sip/numbers`](/api-v1/get/sip-numbers) | List SIP-configured numbers |
    | `GET` | [`/v1/sip/generate-password`](/api-v1/get/sip-generate-password) | Generate a strong SIP password |
    | `PATCH` | [`/v1/sip/config`](/api-v1/patch/sip-config) | Save advanced settings (not yet applied to calls) |
  </Accordion>

  <Accordion title="Discovery and testing">
    | Method | Endpoint | Description |
    |---|---|---|
    | `POST` | [`/v1/sip/parse-destination`](/api-v1/post/sip-parse-destination) | Parse and validate a SIP destination |
    | `POST` | [`/v1/sip/discover`](/api-v1/post/sip-discover) | Auto-discover endpoint settings |
    | `GET` | [`/v1/sip/discover/status`](/api-v1/get/sip-discover-status) | Poll discovery progress |
    | `POST` | [`/v1/sip/test-call`](/api-v1/post/sip-test-call) | Send a test call to your endpoint |
    | `GET` | [`/v1/sip/test-call/status`](/api-v1/get/sip-test-call-status) | Get test call status and trace |
  </Accordion>

  <Accordion title="Monitoring">
    | Method | Endpoint | Description |
    |---|---|---|
    | `GET` | [`/v1/sip/firewall-ips`](/api-v1/get/sip-firewall-ips) | Get Bland's IPs and ports |
    | `GET` | [`/v1/sip/outbound-setup`](/api-v1/get/sip-outbound-setup) | Get outbound server details for PBX config |
    | `GET` | [`/v1/sip/status`](/api-v1/get/sip-status) | Get trunk health |
    | `GET` | [`/v1/sip/calls`](/api-v1/get/sip-calls) | Get SIP call logs |
  </Accordion>

  <Accordion title="Number porting">
    | Method | Endpoint | Description |
    |---|---|---|
    | `GET` | [`/v1/sip/port/check`](/api-v1/get/sip-port-check) | Check portability |
    | `POST` | [`/v1/sip/port/document`](/api-v1/post/sip-port-document) | Upload proof of ownership |
    | `POST` | [`/v1/sip/port/initiate`](/api-v1/post/sip-port-initiate) | Submit a port request |
    | `GET` | [`/v1/sip/port`](/api-v1/get/sip-port-requests) | List port requests |
