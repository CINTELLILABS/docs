Bring your own carrier to Bland. Point calls from your carrier, PBX, or contact center at Bland to be answered by an agent, or have Bland place calls out through your SIP provider.

<Note>
**SIP is organization scope only.** Find it at **All agents**, under **Dispatch**, then **Phone numbers**, then the **SIP** tab. Inside a single agent there is no Phone numbers item, so switch to **All agents** in the scope selector first.
</Note>

## How it works

```text
Inbound:   Caller ──> your carrier or PBX ──SIP/TLS──> Bland agent
Outbound:  Bland agent ──SIP/TLS──> your carrier or PBX ──> Callee
```

- **Trunks** hold the connection to your SIP infrastructure: the endpoint, transport, and authentication. You set them up once.
- **Numbers and DIDs** attach to a trunk and inherit its settings. Each number can route inbound, outbound, or both. E.164 numbers, DIDs, and extensions are all supported.
- **Security is required.** Signaling runs over TLS on port 5061 and audio over SRTP. Bland does not accept plain UDP or port 5060.

## Quick start

<Steps>
  <Step title="Create a trunk">
    On the **SIP** tab, click **Create trunk** and follow the [setup wizard](/agents/sip-setup). It asks for your provider's endpoint, checks it, and shows the IPs to allow-list.
  </Step>
  <Step title="Attach numbers">
    Add the numbers or DIDs that should route through the trunk, then assign an agent to each one under **Phone numbers**.
  </Step>
  <Step title="Place or receive a call">
    Inbound calls to an attached number reach its agent. For outbound, use a trunk number as `from`:

    ```bash
    curl -X POST https://api.bland.ai/v1/calls \
      -H "Authorization: Bearer <token>" \
      -H "Content-Type: application/json" \
      -d '{
        "phone_number": "+14155550123",
        "from": "+12341234123",
        "task": "Say hi to the nice person!"
      }'
    ```
  </Step>
</Steps>

## API

Every SIP endpoint is under `/v1/sip` and authenticates with your API key. Parameters for each endpoint are in the [API reference](/api-v1/post/sip-attach).

<AccordionGroup>
  <Accordion title="Trunks">
    | Method | Endpoint | Description |
    |---|---|---|
    | `POST` | `/v1/sip/trunks` | Create a trunk |
    | `GET` | `/v1/sip/trunks` | List trunks |
    | `GET` | `/v1/sip/trunks/:id` | Get a trunk and its attached numbers |
    | `PATCH` | `/v1/sip/trunks/:id` | Update a trunk |
    | `DELETE` | `/v1/sip/trunks/:id` | Delete a trunk |
    | `POST` | `/v1/sip/trunks/:id/test-connection` | Send a SIP OPTIONS reachability ping |
  </Accordion>
  <Accordion title="Numbers and configuration">
    | Method | Endpoint | Description |
    |---|---|---|
    | `GET` | [`/v1/sip`](/api-v1/get/sip-config) | Get SIP config for a phone number |
    | `POST` | [`/v1/sip/attach`](/api-v1/post/sip-attach) | Attach numbers and DIDs to a trunk |
    | `POST` | [`/v1/sip/update`](/api-v1/post/sip-update) | Update one direction's settings |
    | `POST` | [`/v1/sip/detach`](/api-v1/post/sip-detach) | Remove SIP configuration |
    | `GET` | [`/v1/sip/numbers`](/api-v1/get/sip-numbers) | List SIP-configured numbers |
    | `GET` | [`/v1/sip/generate-password`](/api-v1/get/sip-generate-password) | Generate a strong SIP password |
    | `PATCH` | [`/v1/sip/config`](/api-v1/patch/sip-config) | Save advanced settings (not yet applied to calls) |
  </Accordion>
  <Accordion title="Discovery and testing">
    | Method | Endpoint | Description |

    | `GET` | [`/v1/sip/discover/status`](/api-v1/get/sip-discover-status) | Poll discovery progress |
