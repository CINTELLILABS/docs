Conversations is the record of everything your agents have done. Every call, every message thread, every web chat, in one list you can filter, read, and export.

It is also where you go when something went wrong and you need to know exactly what was said.

<Note>
Searching for call logs? This is it. Voice, messaging, and web chat all land in the same list.
</Note>

## Prerequisites

- An agent that has taken at least one conversation, from [Dispatch](/agents/dispatch)

## Where conversations live

**Conversations** appears at two scopes, under **Monitor** in the sidebar.

| Scope | Tabs |
|---|---|
| **All agents** | Conversations, Active, Contacts |
| Inside an agent | Conversations, Contacts |

**Active** is organization-wide only. It watches calls that are happening right now, and the stream behind it has no per-agent view.

<Warning>
At **All agents**, the list holds calls and message threads. It does not hold web chat.

A web chat conversation appears only on its agent's **Conversations** tab. If you are looking for one and cannot find it, switch the sidebar selector to the agent.
</Warning>

## What a row is

One row is one conversation. A voice row is one call. A messaging or web chat row is one thread, which already covers every message in it.

A row is never a person's whole history, in either view mode.

The **Channel** column tells you which kind you are looking at, and **Length** follows it: `4:12` for a call, `9 msgs` for a thread.

### Chronological and Threaded

The two tabs on the right of the toolbar switch view mode, and the list opens on **Chronological**: newest first, one flat row per conversation.

**Threaded** groups conversations by the person on the other end, using the last ten digits of their number, so a call and an SMS to the same number sit together. Each group lands where its newest member would have been, and members run oldest to newest inside it, joined by a connector line.

It still draws one row per conversation. Threading changes the order, not the unit.

<Note>
Threading happens in your browser, over the rows already loaded. A conversation on a page you have not scrolled to yet is not in the group.

Scroll further, or use **Load more**, before you conclude that someone only called once.
</Note>

## Find a conversation

The toolbar has five ways to narrow the list, and it is worth knowing which run on the server and which run in your browser.

### The search box

Searches the rows already loaded, across four things: the contact's number, the contact's name, the agent or pathway name, and the conversation ID.

It does not search transcripts. For that, open a conversation and use the search field inside it.

### Call source

The select beside the search box reads **Live calls**, and that is a filter.

<Warning>
Simulated calls are hidden by default.

Change **Call source** to **Simulated calls** or **All calls** to see them. A simulated row carries a **Simulated** badge in the **Contact** column, which is the only place it is marked, so it disappears if you hide that column.

Picking **Simulated calls** also empties the list of message threads and web chats, because simulations are voice only.
</Warning>

### Filter

The **Filter** button opens a condition builder. Pick a channel, then add conditions on **Status**, **Direction**, **Escalation**, **QC tags**, or **Contact**. With more than one condition you get an **All** and **Any** switch, and it starts on **All**.

Name a set of conditions under **Saved filters** and it stays in this browser.

### Saved views

The chips above the toolbar are one-click filter presets. Two ship with the product: **Failed & No-Answer** and **Escalated**.

<Warning>
A saved view you create does not survive a page reload. Saved filters, under the **Filter** button, do.

If you built something you want to keep, build it as a saved filter.
</Warning>

### Sort and columns

Sorting is behind the **Sort** button, not the column headers. Clicking a header does nothing. There are two fields to sort on, **Started** and **Last activity**, and a **Newest** and **Oldest** switch.

The **Columns** button shows all twenty. Eleven are on to start with. The ones worth knowing about:

| Column | Why you would turn it on |
|---|---|
| **To** and **From** | The literal numbers on the record. **Contact** shows the other party, which is usually what you want, but not when you are chasing a specific line. |
| **Dispositions** | The outcomes the call was tagged with. |
| **QC tags** | Your own review tags. |
| **Error** | Why a failed call failed, without opening it. |
| **Batch ID** | Which batch a call came from. |

Your choice is stored in this browser, not on your account.

## Read a conversation

Click a row and a panel opens on the right. The page behind it stays live, so you can keep working the list.

Drag the left edge to make it wider, and use the chevrons at the top to step to the previous or next conversation in the list you filtered.

### A call

The middle of the panel is the call itself: an event strip across the top, the timeline under it, and the recording pinned to the bottom if there is one. Click an event in the strip and both the timeline and the audio jump to it.

The timeline has its own search, and on a call that ran a pathway it has three views: **Transcript**, **Detail**, and **Logs**. It opens on **Transcript**.

Each turn carries actions worth knowing: **Raw LLM context** shows exactly what the agent was given to work from, **Edit node** takes you to the step that produced the turn, and **Open turn in Testbed** opens [Testbed](/agents/testbed) pinned to that node with that turn's input.

### A message thread or web chat

You get the transcript, with speakers labelled **Agent**, **User**, and **Rep**. A web chat thread loads newest first, with **Load earlier messages** above it.

On a message thread you can also step in yourself. **Take over** hands the conversation to you, or you can send a single message as a human and leave the agent running. **End conversation** closes the thread. These need an enterprise plan.

A message that failed to send can be retried from its own bubble.

### The right-hand column

Eleven collapsible sections, and only **Metadata** starts open. **Notes**, **Memory**, **Variables**, **Outcomes**, **Webhook & Tools**, **Citations**, **Pathway Tags**, **QC Tags**, **Guardrails & Alerts**, and **Metrics** follow it.

**Notes** are a voice-only feature. On a message thread the section says so.

Hide the whole column with the panel toggle at the top when you want the transcript full width.

### Open in Testbed

The test-tube icon in the panel's top bar opens the whole conversation in [Testbed](/agents/testbed). It is an icon rather than a labelled button, and it appears on calls only.

There is also a **Testbed** button in the list toolbar, which opens it empty.

## Flag what needs looking at

Every voice row has a **Flag** button at the far right. Flagging opens an issue: give it a name, a severity, and a description, or attach the call to an issue that already exists. A flagged call shows a **Flagged** badge afterwards.

To do several at once, tick the rows and use **Add to Issue** in the bar that appears at the bottom. Issues hold calls, so any message threads in your selection are counted and skipped.

## Export

The download icon in the toolbar opens **Export conversations**.

<Warning>
The export is not what is on your screen.

It runs on the server, over the date range you pick, and it keeps only the filters the server knows about: call source, agent, experiment, batch. Your search box, your conditions, your saved view, and your channel pick are all applied in the browser, so none of them reach the export.

Filter down to twelve failed calls, press Export, and you get every conversation in the window.
</Warning>

Calls and message threads export as separate files. Pick one under **Data to export**.

The rest of the modal is the date range, which defaults to the last 30 days and cannot exceed 180, a timezone the range is read in, the email address the file goes to, and **Exclude columns** for trimming the file. Transcripts are excluded from a call export by default, because they are enormous.

You do not get a download. The job runs in the background and emails you a link when it finishes.

## Contacts

**Contacts** is the people on the other end, built up as they interact with your agents. One row per person, with how many messages they have sent, how many of your agents they have met, and what the agent remembers about them.

This tab is organization-wide even when you open it inside an agent.

Click a row for the profile: their details in your organization's own schema, then **Memory**, **Agents**, **Timeline**, **CRM**, and **Raw**.

**Profile** in the header edits the schema itself, the fields every contact record carries and the patterns they are validated against.

**CRM sync** connects HubSpot or Salesforce over OAuth and keeps them fed: contact identity, summaries, memory entities, deals and opportunities, and interaction history, each switchable on its own.

<Note>
Memory is covered lightly here because it belongs to the contact rather than to any one conversation. A conversation's own **Memory** section shows what that conversation contributed.
</Note>

## Active

**Active** is the calls happening right now, at organization scope only. ID, status, a duration that ticks, from, to, and the objective.

Click a row for a live transcript as it happens.

## Common failures

<AccordionGroup>
  <Accordion title="A conversation you know happened is not in the list">
    Three things hide conversations by default. **Call source** is on **Live calls**, so simulations are out. A web chat only appears inside its agent, not at **All agents**. And the list pages as you scroll, so something older may simply not be loaded yet.
  </Accordion>

  <Accordion title="Search does not find a phrase you remember">
    The search box matches the contact, the agent, and the ID. It does not read transcripts. Open a conversation and use the search field inside the panel.
  </Accordion>

  <Accordion title="Clicking a column header does nothing">
    Headers are not sort controls. Use the **Sort** button, which sorts on **Started** or **Last activity**.
  </Accordion>

  <Accordion title="A column is always blank">
    **Issues** does not fill in yet, even on a call you have flagged. Turn it off under **Columns** if the empty space bothers you, and use the **Flagged** badge on the row instead.
  </Accordion>

  <Accordion title="A saved view you made is gone">
    Saved views live for one page load. Rebuild it under **Filter**, as a saved filter, which persists in this browser.
  </Accordion>

  <Accordion title="The export has far more in it than the list showed">
    Expected. The export keeps only the server-side filters. See the warning under Export for which ones those are.
  </Accordion>

  <Accordion title="A row reads No Answer and you know the call connected">
    The status chip falls back to **No Answer** for any status it does not recognize. Open the conversation and read **Metadata** for what actually happened.
  </Accordion>
</AccordionGroup>
