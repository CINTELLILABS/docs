Conversations is the record of everything your agents have done. Every call, every message thread, every web chat, in one list you can filter, read, and export.

It is where you go when something went wrong and you need to know exactly what was said.

<Note>
  Searching for call logs? This is it. A call is a conversation now, and the
  separate lists for calls, messages and web chat are one list.
</Note>

## Prerequisites

- An agent that has taken at least one conversation, from [Dispatch](/agents/dispatch)

## Where conversations live

Conversations appears at two scopes, under Monitor in the sidebar.

The selector at the top of the sidebar decides which one you are on. It reads All agents for the whole organization, or the agent's name when you are inside one.

| Scope           | Tabs                                      |
| --------------- | ----------------------------------------- |
| **All agents**  | Conversations, **Active calls**, Contacts |
| Inside an agent | Conversations, Contacts                   |

**Active calls** is at All agents only: the stream behind it has no per-agent view.

Web chat appears only on its agent's Conversations tab, not at All agents.

## What a row is

One row is one conversation. A voice row is one call. A messaging or web chat row is one thread, which already covers every message in it.

The Channel column tells you which kind you are looking at, and Length follows it: `4:12` for a call, `9 messages` for a thread.

### Chronological and Threaded

The two tabs on the right of the toolbar change how the list is drawn, and it opens on **Chronological**: newest first, one flat row per conversation.

Threaded groups conversations by the person on the other end, using the last ten digits of their number, so a call and an SMS to the same number sit together. Each group lands where its newest member would have been. Inside it, members run oldest to newest, joined by a connector line.

Threaded ignores the Sort control: groups are always newest first. Changing the sort still changes which rows load, so the list can shift under you without reordering.

It still draws one row per conversation. Threading changes the order, not the unit.

### Calls in progress

A call shows up in Conversations while it is still happening. You do not have to wait for it to end. This works at All agents, inside an agent, and in the conversations on the overview page.

The list refreshes every five seconds while it is on screen, so new calls appear without a reload. When a call ends, its completed record replaces the in-progress row, so the call is never listed twice.

<Note>
Threading happens in your browser, over the rows already loaded. A conversation on a page you have not scrolled to yet is not in the group.

Scroll further, or use **Load more**, before you conclude that someone only called once.

</Note>

## Find a conversation

The list opens on the newest conversations and pages as you scroll, with a **Load more** button under the table. Use **Filter** to narrow the records, including by date.

Use the search box, agent selector, call source, and **Filter** to narrow the list. Search only checks loaded rows; **Filter** checks records on the server.

### The search box

Searches the rows already loaded, across the contact's number, the contact's name, the pathway name, and the conversation ID.

An agent's name on a call is not in that list. Use the Agent filter for that.

It does not search transcripts. For that, open a conversation and use the search field inside it.

If you know the conversation exists and search finds nothing, it is almost always still unloaded. Press **Load more** and search again.

### Agent

Pick one agent or several, and the list narrows to their conversations.

It only exists at All agents. Inside an agent you are already narrowed to one.

### Call source

The select beside the search box offers **Live**, **Simulated**, and **Live and simulated**. It starts on **Live**.

<Warning>
Simulated calls are hidden by default.

Select **Simulated** or **Live and simulated** to see them. A simulated row carries a Simulated badge in the Contact column. That is the only place it is marked, so hiding the column hides the badge.

Picking **Simulated** also empties the list of message threads and web chats, because simulations are voice only.

</Warning>

### Filter

**Filter** opens a server-side condition builder. Choose **Channel**, select **All conditions** or **Any condition** under **Match**, and add conditions on call-log fields. Select **Apply filters** to use them or **Clear filters** to remove them.

A condition that only applies to calls hides messaging conversations. On an agent's page, applying any condition also hides web chats. Clear the conditions to see those conversations again.

### Views

**Views** under the toolbar contains **Failed & no answer**, **Escalated**, and your organization's shared views. A shared view saves a set of conditions for reuse across the organization.

### Sort and columns

Sorting is behind the Sort button, not the column headers. Clicking a header does nothing. There are two fields to sort on, Started and Last activity, and a **Newest** and **Oldest** switch.

The **Columns** button shows all twenty, eleven of them on to start with. Of the nine that are off:

| Column              | Why you would turn it on                                                                                                                            |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| **To** and **From** | The literal numbers on the record. **Contact** shows the other party, which is usually what you want, but not when you are chasing a specific line. |
| **Dispositions**    | What each call's dispositions produced, when you are auditing a batch without opening each one.                                                     |
| **QC tags**         | Your own review tags, when you are working a review queue off the list.                                                                             |
| **Error**           | Why a failed call failed, without opening it.                                                                                                       |
| **Batch ID**        | Which batch a call came from, when one batch behaved differently from the rest.                                                                     |

Turning on **Dispositions** adds one column per key your agent's dispositions produce, headed by the key. When two dispositions share a key, the column title starts with the disposition name. Each cell holds the value the call's latest run produced for that key, or **Pending**, **No value**, **Error**, or **Cancelled**.

A single **Dispositions** column of tag badges also appears while any call in view has legacy outcomes, or while there are no key columns yet.

Your choice is stored in this browser, not on your account.

## Read a conversation

Click a row and a panel opens on the right. The page behind it stays live, so you can keep working the list.

Drag the left edge to make it wider, and use the chevrons at the top to step to the previous or next conversation in the list you filtered.

The copy icon in the panel header offers **Copy conversation ID**, and on a call **Copy all logs**, which is a raw JSON dump rather than a readable transcript.

**Copy transcript** beside it works on message threads and web chat. On a call it stays disabled: a call's words live in the timeline, which has a search of its own.

On a call there is also a **Flag**, the same one as on the row.

### A call

The middle of the panel is the call itself: an event strip across the top, the timeline under it, and the recording pinned to the bottom if there is one. Click an event in the strip and both the timeline and the audio jump to it. Click an agent or caller message in the timeline and the recording jumps to where that turn starts. This works before you press play, too.

The timeline has its own search and three tabs: **Conversation**, **Variables**, and **Logs**. The display selector offers **Messages only**, **Events**, **Expanded events**, and **Event JSON**.

Hover a turn and the actions it supports appear, up to four of them.

| Action                     | What it does                                                                                |
| -------------------------- | ------------------------------------------------------------------------------------------- |
| Raw LLM context            | Shows exactly what the agent was given to work from.                                        |
| Edit node                  | Takes you to the step in the [agent builder](/agents/agent-builder) that produced the turn. |
| Open turn in Testbed       | Opens [Testbed](/agents/testbed) pinned to that node, with that turn's input.               |
| Report transcription issue | For when the words on screen are not the words that were said.                              |

### A message thread or web chat

You get the transcript, with speakers labelled Agent, User, and Rep. A web chat thread loads newest first, with **Load earlier messages** above it.

On a message thread you can also step in yourself, on an enterprise plan. **Take over** hands the conversation to you and pauses the agent. The agent stays paused until you press **Return to agent**. You can also send one message as a human and leave the agent running. **End conversation** ends it. The agent stops replying, and the customer's next message starts a new conversation.

A message that failed to send can be retried from its own bubble.

### The right-hand column

Only Metadata starts open, and it is the one that answers how the conversation went. It holds the ID, the channel, the direction, the agent, when it started and ended, and a written summary at the end. Duration and cost are on calls; a message count is on threads.

Notes, Memory, Pathway tags and QC tags follow it, closed, and carry what you and the agent put there.

On a call, **Dispositions** lists each disposition that ran on it. Under the disposition name, a callout says what intelligence its values ran at, such as **Low**, **High**, or **Low + High** when values differ. It also says whether results arrive in realtime or within 24 hours. Below the callout, each key sits beside the value the run produced. A run still in progress reads **Running on…** and shows its keys as **Pending**. Legacy outcome tags stay listed underneath. If the section fails to load, select **Retry**.

**Variables** shows extracted variables from the call record. **Guardrails & issues** shows guardrail triggers or linked issues when available. **Metrics** displays recorded conversation metrics; a section with no recorded data shows its empty state.

Three things here sound alike and are not. The Dispositions section and columns are what your dispositions produced for the call. Status is whether it connected at all. The Disposition row inside Metadata is a messaging-thread field and is not on a call.

Notes are only available on calls.

Hide the whole column with the panel toggle at the top when you want the transcript full width.

### Open in Testbed

The test-tube icon in the panel's top bar opens the whole conversation in [Testbed](/agents/testbed). It is an icon rather than a labelled button, and it appears on calls only.

There is also a **Testbed** button in the list toolbar, which opens it empty.

## Flag what needs looking at

Every voice row has a **Flag** button at the far right, and the same button is in the panel header.

Flagging either opens a new issue, which takes a title, a severity, a description and a note, or adds the call to one that already exists, which still takes a note. The note is required on both, and the submit button just stays disabled until you write one.

To do several at once, tick the rows and use **Add to issue** in the bar that appears at the bottom. A new issue there takes a title, severity, and description. Only calls can be added from here, so any message threads in your selection are counted and skipped. Attach messaging conversations from the issue's **Evidence** tab.

An issue you create from a call belongs to the agent that handled that call. To see one agent's issues, open the agent and select **Issues**. The Issues page in the sidebar still shows every issue in your org.

## Export conversations

The download icon in the toolbar opens **Export conversations**.

<Warning>
The export runs on the server over the date range you choose. It inherits call source, agent, channel, and applicable server-side conditions. Call exports use call conditions; messaging exports use conditions that apply to messaging records. The modal lists inherited conditions under **Filters applied to this export** and identifies ignored conditions.

The search box only narrows loaded rows and does not reach the export. Review the inherited and ignored filters before submitting.

</Warning>

Calls and messaging conversations export as separate files. Pick **Calls** or **Messaging conversations** under **Data to export**. There is no web chat export.

The rest of the modal is the date range, the timezone it is read in, the email address the file goes to, and **Exclude columns** for trimming the file. The range defaults to the last 30 days and cannot exceed 180. Transcripts are excluded from a call export by default, because they are enormous.

You do not get a download. The job runs in the background and emails you a link when it finishes.

## Look up a contact

**Contacts** is the people on the other end, built up as they interact with your agents. One row per person, with how many messages they have sent, how many of your agents they have met, and what the agent remembers about them.

This tab is organization-wide even when you open it inside an agent.

Click a row for the profile: their details in your organization's own schema, then **Conversations**, **Memory**, **Agents**, **CRM**, and **Raw**.

**Edit profile fields** in the header edits the fields every contact record carries and the patterns they are validated against.

**Manage CRM sync** connects HubSpot or Salesforce and keeps them fed: contact identity, summaries, memory entities, deals and opportunities, and interaction history, each switchable on its own.

<Note>
  Memory belongs to the contact, not to any one conversation. A conversation's
  own Memory section shows only what that conversation contributed.
</Note>

## Watch calls in flight

**Active calls** shows the calls happening right now, at All agents only. ID, status, a duration that ticks, from, to, and the objective.

Click a row for a live transcript as it happens. You can also listen in, which is an organization setting: if it is off you get a padlock and a link to turn it on.

Calls in progress also appear on the Conversations tab, at both scopes. Use **Active calls** when you want the live transcript or to listen in.

With nothing running, the empty state's **Get a test call** calls your own number, which is the fastest way to watch the tab work.

## Common failures

<AccordionGroup>
  <Accordion title="A conversation you know happened is not in the list">
    Three things hide conversations by default. Call source is on **Live**, so simulations are out. A web chat only appears inside its agent, not at All agents. And the list pages as you scroll, so something older may not be loaded yet. Change Call source, switch the selector to the agent, or press **Load more**.
  </Accordion>

<Accordion title="Search does not find a phrase you remember">
  The search box matches the contact and the conversation ID, on rows already
  loaded. It does not search transcripts. Open a conversation and use the
  timeline's search.
</Accordion>

<Accordion title="Clicking a column header does nothing">
  Use the Sort button instead. It sorts on Started or Last activity.
</Accordion>

<Accordion title="A shared view is missing">
  Shared views belong to your organization. Check that you selected the right
  organization, and retry loading the views if the list shows an error.
</Accordion>

<Accordion title="The export has far more in it than the list showed">
  Check **Filters applied to this export** and the ignored-filter notice. Search
  only narrows loaded rows, and conditions for the other resource do not carry
  over. Choose the matching export resource and narrow its date range.
</Accordion>

  <Accordion title="A row reads No answer and you know the call connected">
    The status chip falls back to **No answer** for any status it does not recognize. Open the conversation and read Metadata for what actually happened.
  </Accordion>
</AccordionGroup>
