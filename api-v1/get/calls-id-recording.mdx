---
title: "Get Call Recording"
api: "GET https://api.bland.ai/v1/recordings/{call_id}"
description: "Retrieve an audio stream for a call recording."
---

New organizations require authentication to play a call recording. A recording link on its own will not play; the request must present an API key or a signed-in dashboard session. Existing organizations are unchanged.

You can adjust this at any time under **Settings → General → Recording preferences**, or through `recording_lifespan_days` on [`PATCH /v1/orgs/{org_id}/properties`](/api-v1/patch/org_properties): `0` always requires authentication, `1` to `1825` allows unauthenticated playback for that many days after the call, and `-1` never requires it.

### Headers

<ParamField header="authorization" type="string" required={true}>
  Your API key for authentication.
</ParamField>

<ParamField header="content-type" type="string" required={false}>
  Audio content type requested: `"audio/mpeg"` (MP3) or `"audio/wav"` (WAV). Defaults to WAV.
</ParamField>

### Path Parameters

<ParamField path="call_id" type="string" required>
  The unique identifier of the call for which you want to retrieve its recording.
</ParamField>

### Query Parameters

<ParamField query="..." type="any" required={false}>
  Any additional query parameters will be passed through to the underlying recording URL.
</ParamField>

### Response

<ResponseField name="data" type="audio stream">
  The audio recording stream of the call, in the requested or default format (WAV).
</ResponseField>

<ResponseField name="errors" type="null|array">
  `null` on success, or an array of error objects if access fails.
</ResponseField>

<ResponseExample>
```json Response (not found)
{
  "data": null,
  "errors": [
    {
      "error": "CALL_RECORDING_NOT_FOUND",
      "message": "Call recording not found"
    }
  ]
}
```
</ResponseExample>
