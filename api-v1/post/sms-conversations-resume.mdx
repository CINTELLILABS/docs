---
title: "Resume SMS Conversation from Handoff"
api: "POST https://api.bland.ai/v1/sms/conversations/{id}/resume"
description: "Return a handed-off SMS conversation to the AI agent, optionally jumping to a pathway node or sending a transition message."
---

<Info>
  **Enterprise feature** — Human handoff is available on Enterprise plans. Contact your Bland representative for access.
</Info>

Ends the human handoff on the conversation and returns control to the AI agent. Optionally jumps the pathway to a specific node before the agent picks up, and optionally sends one transition message (either verbatim or generated by the agent).

Fires the `human_handoff_ended` status webhook when the handoff was active. The inactivity timeout is re-armed. See [Post-Call Webhooks](/tutorials/post-call-webhooks) for payload details.

### Headers

<ParamField header="authorization" type="string" required>
  Your API key for authentication.
</ParamField>

<ParamField header="idempotency-key" type="string" required={false}>
  A unique key to prevent duplicate sends when `message` or `generate_reply` is used.
</ParamField>

### Path Parameters

<ParamField path="id" type="string" required>
  The ID of the SMS conversation to resume.
</ParamField>

### Body Parameters

<ParamField body="node_id" type="string" required={false}>
  ID of a pathway node to jump to before the agent resumes. Use this to route the conversation to a specific step (for example, a confirmation node after the rep closed a deal).
</ParamField>

<ParamField body="message" type="string" required={false}>
  A verbatim transition message to send from the agent as the handoff ends. Maximum 1600 characters. Cannot be combined with `generate_reply`.
</ParamField>

<ParamField body="generate_reply" type="boolean" required={false}>
  When `true`, the agent generates its next reply immediately based on the pathway and conversation history. Cannot be combined with `message`.
</ParamField>

<ParamField body="actor" type="string" required={false}>
  Identifier for the person or system resuming the conversation.
</ParamField>

### Response

<ResponseField name="data.message" type="string">
  Confirmation text.
</ResponseField>

<ResponseField name="data.was_active" type="boolean">
  `true` if a handoff was active before this call, `false` if the conversation was not handed off (a no-op resume).
</ResponseField>

<ResponseField name="data.conversation" type="object">
  Summary of the conversation after the resume, including `id`, `is_active`, `current_node_id`, `human_handoff_at` (now `null`), and `updated_at`.
</ResponseField>

<ResponseField name="data.status" type="string">
  `"processing"` when a transition message was queued.
</ResponseField>

<ResponseField name="data.message_id" type="string">
  ID of the transition message, if one was sent.
</ResponseField>

<ResponseField name="errors" type="null|array">
  `null` on success, or a list of error objects if the request failed.
</ResponseField>

<RequestExample>

```bash cURL
curl -X POST https://api.bland.ai/v1/sms/conversations/conv_abc123/resume \
  -H "authorization: YOUR_API_KEY" \
  -H "content-type: application/json" \
  -d '{
    "node_id": "node_confirm_rate",
    "message": "Thanks for your patience — the agent will confirm the details next.",
    "actor": "rep_42"
  }'
```

</RequestExample>
