---
title: "Analyze Call with AI"
api: "POST https://api.bland.ai/v1/calls/{call_id}/analyze"
description: "Analyze a completed call's transcript with AI, using a goal and a list of questions."
---

### Headers

<ParamField header="authorization" type="string" required>
  Your API key for authentication.
</ParamField>

### Path Parameters

<ParamField path="call_id" type="string" required>
  The unique identifier for the call to be analyzed.
</ParamField>

### Request Body

<ParamField body="goal" type="string" default="">
  The overall purpose of the call. Provides context for the analysis to guide how the questions and transcript are interpreted. Optional; defaults to an empty string.
</ParamField>

<ParamField body="questions" type="string[][]" required>
  A non-empty array of questions to be analyzed for the call.

  Each question must be an array of exactly two strings: the question text and the expected answer type (e.g., "string", "boolean").

  Fairly flexible in terms of the expected answer type, and unanswerable questions will default to `null`.

  Examples:
  ```json
  "questions": [
        ["Who answered the call?", "human or voicemail"],
        ["Positive feedback about the product: ", "string"],
        ["Negative feedback about the product: ", "string"],
        ["Customer confirmed they were satisfied", "boolean"]
    ]
  ```
</ParamField>

<ParamField body="call_id" type="string">
  Optional. When present, overrides the `call_id` in the path.
</ParamField>

### Response

<ResponseField type="string" name="status">
  `success` if the request was successful.
</ResponseField>

<ResponseField type="string" name="message">
  `"Successfully analyzed call"`.
</ResponseField>

<ResponseField type="array" name="answers">
  The analyzed answers, in the same order as `questions`.
</ResponseField>

<ResponseField type="string[][]" name="questions">
  The `questions` array you sent, echoed back.
</ResponseField>

<ResponseField type="number" name="credits_used">
  Credits charged for this analysis. The charge is token-based: longer transcripts and more questions cost more.
</ResponseField>

<Note>
  Invalid input (for example a missing or malformed `questions` array, or a `call_id` that does not belong to your organization) is returned as a `500` with the shape `{ "error": "<reason>", "message": "Server error analyzing call" }`, not as a `400`. Check `error` for the specific reason.
</Note>

<ResponseExample>
```json Response
{
    "status": "success",
    "message": "Successfully analyzed call",
    "answers": [
        "human",
        "Customer found the product sturdy and reliable",
        "A bit heavy",
        true
    ],
    "questions": [
        ["Who answered the call?", "human or voicemail"],
        ["Positive feedback about the product: ", "string"],
        ["Negative feedback about the product: ", "string"],
        ["Customer confirmed they were satisfied", "boolean"]
    ],
    "credits_used": 0.0042
}
```

```json Error (500)
{
    "error": "Invalid 'questions' parameter - must be non-empty array",
    "message": "Server error analyzing call"
}
```
</ResponseExample>
