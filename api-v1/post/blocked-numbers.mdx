---
title: "Create Block Rules"
api: "POST https://api.bland.ai/v1/blocked_numbers"
description: "Create one or more block rules to prevent specific phone numbers from reaching your inbound numbers."
---

<Info>
  **Call Blocking**: blocked numbers are rejected before reaching any agent. Blocking can apply globally or to specific inbound lines.
</Info>

### Headers

<ParamField header="authorization" type="string" required>
  Your API key for authentication.
</ParamField>

### Body Parameters

<ParamField body="numbers" type="string[]" required>
  A list of phone numbers to block, formatted in E.164 (e.g., `+14155551234`). 1 to 10 numbers per request. Numbers are validated and standardized; an invalid entry fails the whole request with `400 INVALID_PHONE_NUMBER`.
</ParamField>

<ParamField body="is_global" type="boolean" required>
  Set to `true` to block the numbers globally across all inbound numbers. Set to `false` to scope the block to a specific `inbound_number`.
</ParamField>

<ParamField body="inbound_number" type="string">
  The E.164 formatted inbound number to associate the block with. Required when `is_global` is `false` (`400 INBOUND_NUMBER_REQUIRED` otherwise). When `is_global` is `true` it must be omitted or `null`; sending a value fails schema validation (`400 VALIDATION_ERROR`).
</ParamField>

<ParamField body="reason" type="string">
  Optional text to describe the reason for blocking. `null` is accepted.
</ParamField>

### Response

Returns `201 Created` with the standard `{ "data": ..., "errors": null }` envelope.

<ResponseField name="data.created_count" type="number">
  The number of entries in `numbers`.
</ResponseField>

<ResponseField name="data.blocks" type="array">
  List of block rule objects that were created. `id` is a string (a UUID, or a legacy integer ID as a string) and is used as `block_id` on the other endpoints.
</ResponseField>

<ResponseField name="errors" type="null|array">
  `null` on success. On failure `data` is `null` and each error has `error` and `message` (schema errors also carry `field`):

  - `400` `VALIDATION_ERROR`, `INVALID_PHONE_NUMBER`, `INBOUND_NUMBER_REQUIRED`
  - `500` `SERVICE_ERROR`
</ResponseField>
