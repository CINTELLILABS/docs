---
title: "Update Organization's Service Version"
api: "PATCH https://api.bland.ai/v1/orgs/{org_id}/versions/{service}"
description: "Update the current version of a specified service for an organization."
---

### Headers

<ParamField header="authorization" type="string" required>
  Your API key for authentication.
</ParamField>

<Note>
Requires the `owner` or `admin` role. A non-member caller or a caller without the required role gets a `500` response with error `ORG_VERSION_UPDATE_FAILURE` and the reason in `message` (for example `Unauthorized`), not a `403`.
</Note>

### Path Parameters

<ParamField path="org_id" type="string" required>
  The unique identifier of the organization. Must be a UUID, otherwise the request fails with `400 INVALID_UUID`.
</ParamField>

<ParamField path="service" type="string" required>
  The name of the service whose version you want to update.
  <br/>Valid values: `"api_server"`, `"ws_server"`
</ParamField>

### Body

<ParamField body="version" type="string" required>
  The `id` of the version to switch to. It must appear in [List Organization's Service Versions](/api-v1/get/org_list_versions) for the same `service`.
</ParamField>

### Constraints

- The version must be currently supported for the given `service` and have a production build. Otherwise the request fails with `Invalid Version/Version is no longer supported: <version>`.
- For non-enterprise organizations, switching versions moves the organization to the placement group that serves that version. Enterprise organizations keep their placement group and have the version pinned on their dedicated deployment.

### Response

<ResponseField name="data" type="null">
  Always `null` upon successful update.
</ResponseField>

<ResponseField name="errors" type="null | array">
  `null` on success. On failure, `data` is `null` and `errors` contains one entry with `error: "ORG_VERSION_UPDATE_FAILURE"` and the reason in `message` (status `500`).
</ResponseField>

<ResponseExample>

```json Response
{
  "data": null,
  "errors": null
}

```
</ResponseExample>
