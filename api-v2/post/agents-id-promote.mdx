---
title: "Promote Agent to Production"
api: "POST https://api.bland.ai/v2/agents/{agent_id}/promote"
description: "Pin production to the version in staging, or to a version you name."
---

### Overview

Moves the agent's `production` pointer and records a deployment. Phone numbers attached to the agent begin answering with the promoted version, and any active experiment whose baseline is production ends with `completed_reason` set to `baseline_changed`.

- With an empty body, production moves to whatever `staging` is pinned to. The deployment carries that version's original semver; no new number is minted.
- With `version_id`, that exact version goes to production, from the dev timeline or an open branch. `staging` is repointed to it in the same step. A version that was never published is given a semver using `bump`.

The server does not run evaluations, but it enforces them. When the staging evaluation configuration has at least one required evaluation, the promote checks the newest `staging` check run that scored the version being promoted. It returns `409 CHECKS_BLOCKED` when there is no such run, when the run is still in progress, errored, or was cancelled, when a required evaluation failed, or when the run used a different configuration than the one saved now. Start a run on `staging` with [Start Check Run](/api-v2/post/agents-id-environments-env-check-runs) before you promote, or send `force: true` to skip the check for this one promote.

A version that references an environment variable with no `production` value is refused with `409 AGENT_VARIABLE_UNRESOLVED`, even with `force`.

Requires an admin, owner, operator, or prompter role.

### Headers

<ParamField header="authorization" type="string" required>
  Your API key for authentication.
</ParamField>

### Path Parameters

<ParamField path="agent_id" type="string" required>
  The agent's unique identifier.
</ParamField>

### Body Parameters

All body parameters are optional.

<ParamField body="version_id" type="string">
  ID of a version of this agent to promote instead of the staging pin. It can be on the dev timeline or on an open branch. Returns `404 VERSION_NOT_FOUND` if the ID is not one of this agent's versions, and `409 BRANCH_CLOSED` if its branch was merged or archived.
</ParamField>

<ParamField body="branch_id" type="string">
  The branch you are promoting from. When set, `version_id` must be a version saved on that branch, or the request returns `404 VERSION_NOT_FOUND`. Sending `branch_id` without `version_id` returns `400 INVALID_BRANCH`.
</ParamField>

<ParamField body="bump" type="string" default="patch">
  Which component to increment when `version_id` names a version that was never published: `patch`, `minor`, or `major`. Ignored otherwise. Returns `400 INVALID_BUMP` for any other value.
</ParamField>

<ParamField body="force" type="boolean" default="false">
  Skip the required-evaluation check for this one promote. Also promotes while a migration rollout from a V1 pathway to this agent is live, which otherwise returns `409 ROLLOUT_IN_PROGRESS`. The audit log records the bypass; the deployment does not. Does not skip the variable check. A non-boolean value returns `400 INVALID_FORCE`.
</ParamField>

<ParamField body="expected_staging_version_id" type="string">
  The staging version you reviewed. Applies only without `version_id`. If staging points at a different version when the promote runs, nothing changes and the request returns `409 STAGING_CHANGED`. Sending it with `version_id`, or as an empty or non-string value, returns `400 INVALID_EXPECTED_STAGING_VERSION`.
</ParamField>

### Response

Returns `200` on success.

<ResponseField name="data.semver" type="string">
  The promoted version's number, for example `1.4.0`.
</ResponseField>

<ResponseField name="data.environments" type="array">
  The agent's three environments after the promote. Each has `id`, `env_type` (`dev`, `staging`, or `production`), and `current_version_id` (the pinned version, or `null` if unpinned). `staging` and `production` now point at the same version.
</ResponseField>

<ResponseField name="data.production_moved" type="boolean">
  `false` when production already pinned the version named by `version_id` and only `staging` moved to match it. `true` otherwise.
</ResponseField>

<ResponseField name="errors" type="null | array">
  `null` on success, or a list of error objects if the request failed. Besides the errors above, returns `400 STAGING_UNPINNED` when the body has no `version_id` and nothing has been published to staging, `400 ALREADY_IN_PRODUCTION` when production and staging already pin the version, and `409 PUBLISH_IN_PROGRESS` when another publish or promote for the same agent is running; retry after a moment.
</ResponseField>
