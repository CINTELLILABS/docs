description: "See which folder each of your agents' scenarios is filed in."

### Overview

Returns one entry for every scenario your organization has filed in a folder. The list is flat: each entry names one scenario and its folder. It doesn't list folders, and it doesn't group scenarios by folder.

Scenarios you haven't filed are left out, so the list is empty until you file one with [File Scenario in Folder](/api-v2/put/agents-library-scenario-folders). Migrating a pathway into an agent doesn't file its scenarios. Entries for deleted agents are left out, but an entry stays when its scenario is removed from an agent, so match entries against [List Library Scenarios](/api-v2/get/agents-library-scenarios). Call it with `paginate=true` and walk every page, or you'll miss agents past the first 50. An entry for a node that isn't in the agent's latest saved version won't match until that version is saved.

Folders are shared with legacy pathways. To list, create, rename, or delete folders, use the folder endpoints such as [Get All Folders](/api-v1/get/pathway_folders) and [Create Folder](/api-v1/post/create_pathway_folder). Deleting a folder takes every scenario filed in it out of the folder. [Get Pathways in Folder](/api-v1/get/folder_pathways) lists legacy pathways only, so use this endpoint to see which scenarios are in a folder.

Restricted API keys can't call this endpoint. Use a full-access key.

### Headers

<ParamField header="authorization" type="string" required>
  Your API key for authentication.
</ParamField>

### Response

<ResponseField name="data" type="array">
  One entry per filed scenario.

  <Expandable title="entry">
    <ResponseField name="agent_id" type="string">
      The agent the scenario belongs to.
    </ResponseField>
    <ResponseField name="node_id" type="string">
      The scenario's node ID: the `id` of a scenario from [List Library Scenarios](/api-v2/get/agents-library-scenarios).
    </ResponseField>
    <ResponseField name="folder_id" type="string">
      The folder the scenario is filed in.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="errors" type="null | array">
  `null` on success, or a list of error objects if the request failed.
</ResponseField>
