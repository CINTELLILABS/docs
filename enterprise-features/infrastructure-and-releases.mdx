Runtime releases control the Bland software running your conversations. They are separate from [agent versions and environments](/agents/environments), which control your agent's configuration.

## Infrastructure

Enterprise infrastructure is provisioned according to your organization's deployment configuration. Confirm your compute allocation, scaling, and isolation requirements with your account team before planning a release.

## Choose a release

Open **Settings → Releases**. **Agent releases** shows your current runtime version, deployment status, and version history. Select an available named release and use **Deploy** for that release. Monitor deployment status until it completes before treating the upgrade as ready.

A named release selects its specific build. **Latest** is a rolling release that tracks new builds; it does not pin your organization indefinitely to one build.

Deployment updates run asynchronously. Monitor readiness and failures rather than assuming a successful request means every instance has updated. Coordinate recovery with your account team if a deployment fails.

## Agents canary

**Agents canary** supports moving legacy pathway calls to v2 agents alongside the production runtime.

1. Choose the release in **Agents canary** and deploy it.
2. Wait for the deployment to be running.
3. Use **Enable agents canary** to enable it. Provisioning alone does not enable routing.
4. Test the migration with your account team and [agent experiments](/agents/experiments).

**Tear down canary** asks for confirmation. Calls routed to v2 agents will use the v1 pathway again; the production runtime release stays on its current version. Review migration dependencies before teardown.

## Release canary routing through the API

The separate release-canary API supports a base traffic percentage from 0 to 100 and prioritized routing rules. These controls are not a slider or rule editor on the current Releases page. Ask your account team for the appropriate configuration and access.

For API-managed release canaries, promotion starts a production deployment and teardown removes canary infrastructure asynchronously. Teardown can take several minutes. Neither action is a guarantee of instant rollback or uninterrupted calls.
