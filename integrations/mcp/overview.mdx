The Bland MCP server lets any AI agent work with your Bland account through natural language: build, version, and publish Bland Agents, place and inspect calls, send texts, query analytics, run evals, and search the Bland docs. Tools for legacy pathways are still available.

It's a remote [Model Context Protocol](https://modelcontextprotocol.io) server hosted by Bland. There's nothing to run locally: point your client at the endpoint, sign in with Bland or use your API key, and your agent has the full toolset.

```text
https://api.bland.ai/v1/mcp
```

## How it works

- **Transport:** Streamable HTTP (the current MCP standard). The server is stateless, so there are no sessions to manage and any request can hit any node.
- **Authentication:** [sign in with Bland](/integrations/mcp/oauth) (OAuth; ChatGPT, Claude, and Claude Code today, other clients once dynamic client registration is available), or a full-access Bland API key in the `Authorization` header (`Bearer org_...`), which works with every client. [Restricted keys](/api-v1/post/keys-create#restricted-keys) can't connect. Either way, one organization scopes every tool: an agent connected to your org sees only that org's calls, pathways, and agents. Get a key from the [dashboard](https://app.bland.ai/dashboard/settings), or let an agent obtain its own through the [Agent onboarding API](/platform/connect-your-agent).
- **Rate limits:** 120 requests per minute per organization.
- **Safety:** every tool carries read-only and destructive annotations, so well-behaved clients ask before the agent does anything with side effects (like placing a real phone call). The server doesn't ask for confirmation itself, so keep your client's tool-approval prompts on.

## Discovering the server from a 401

A request that reaches `/v1/mcp` with no credential gets a `401` that tells the client what to do next. Clients that already send a valid `Authorization` header never see it. Two pieces:

- A `WWW-Authenticate` header (RFC 6750):

  ```text
  WWW-Authenticate: Bearer realm="bland", resource_metadata="https://api.bland.ai/.well-known/oauth-protected-resource/v1/mcp", scope="mcp:read mcp:write"
  ```

  A credential that was refused gets `error="invalid_token"` on the same header.

- A JSON-RPC error body whose `error.message` and `error.data` name the header to send, where a human gets a key, and any self-serve signup flows an agent can run on its own: currently [headless onboarding](/platform/agent-headless-onboarding) and the [device-code flow](/platform/connect-your-agent). Each is listed only while it's enabled.

Which piece a client uses depends on what it supports:

- **OAuth clients** follow `resource_metadata` to the protected resource document (RFC 9728). It names the authorization server, `https://api.bland.ai/authorization`, and the scopes `mcp:read` and `mcp:write`. The authorization server's own metadata is at `https://api.bland.ai/.well-known/oauth-authorization-server/authorization` and `https://api.bland.ai/authorization/.well-known/openid-configuration`. From there the client runs the flow on [Sign in with Bland](/integrations/mcp/oauth). Clients that only register dynamically can't complete it yet and need an API key.
- **Agents with no key** read the body, pick a signup flow, obtain their own key, and retry the same MCP call.

## What your agent can do

| Category | Highlights |
| --- | --- |
| **Agents** | Full lifecycle for the Bland Agents platform: create, version, branch, publish to staging, promote to production, manage environment variables. For guided builds, use the [Norm plugin](/integrations/mcp/norm). |
| **Calls** | Place an outbound call (`create_call`), wait for it to finish (`wait_for_call`), stop it (`stop_call`), and fetch its transcript, recording, and summary (`get_call_log`). Pick a voice from Bland's curated set (`list_voices`). |
| **Analytics** | Structured call-analytics queries with grouping, filters, and time ranges (`query_analytics`). |
| **Evals** | List and inspect LLM judges, kick off eval runs over batches of calls. |
| **Docs** | Search and read docs.bland.ai from inside the session (`search_bland_docs`, `get_bland_doc`). |
| **Pathways (Legacy)** | Compile-check a pathway graph before saving (`validate_pathway`), fetch the authoritative schema (`get_pathway_schema`), and get deep node/edge semantics (`get_pathway_context`). |
| **API Reference tools** | One tool per [API Reference](/api-v1/post/calls) page, such as `send_call` for every Send Call field, `send_sms`, and the knowledge base, number, and evals endpoints. |
| **Full API reach** | Over an API key connection, anything else: `bland_api_get` for any GET endpoint, `call_bland_api` for any mutating endpoint. |

See the full [tool reference](/integrations/mcp/tools).

Over an API key connection, the server also ships MCP **prompts** for legacy pathways: `bland_pathways`, `build_pathway`, and `edit_pathway`. They appear as slash commands in clients that support them (like Claude Code). For Bland Agents, use the [Norm plugin](/integrations/mcp/norm) instead.

## Call completion events

Clients that support MCP events on protocol version `2026-07-28`, such as ChatGPT, can subscribe to `call.completed`. Bland then sends a signed webhook to the client each time a phone call in your account finishes. Your agent can react to a finished call without polling. Clients that support events usually manage the subscription for you.

The event covers inbound and outbound phone calls. Web calls and simulations aren't included. Any authenticated connection can subscribe: [sign-in](/integrations/mcp/oauth) or a full-access API key. You don't need a plan or a dedicated number.

### Subscribe

Send the event name, optional filters, and a webhook destination. Leave `arguments` empty (`{}`) to receive every phone call completion in the organization.

```json
{
  "name": "call.completed",
  "arguments": {
    "phone_number": "+14155550100",
    "direction": "inbound",
    "agent_id": "00000000-0000-4000-8000-000000000001"
  },
  "delivery": {
    "mode": "webhook",
    "url": "https://receiver.example/mcp-events",
    "secret": "whsec_<base64-encoded-key>"
  },
  "cursor": null
}
```

| Filter | Description |
| --- | --- |
| `phone_number` | Your number on the call, in E.164 format. That's the `to` number for inbound calls and the `from` number for outbound calls. |
| `direction` | `inbound` or `outbound`. |
| `agent_id` | A Bland Agent in your organization. |

- Bland sends a signed verification challenge to the webhook URL before the subscription activates.
- Subscriptions expire after 24 hours. To renew, send the same request before the `refreshBefore` time in the response.
- Each connection can hold up to 100 active subscriptions.
- To unsubscribe, send the same name, arguments, and webhook URL without a secret.
- `cursor` must be `null`. Bland doesn't replay past events.

### Event payload

```json
{
  "eventId": "call_completed_00000000-0000-4000-8000-000000000002",
  "name": "call.completed",
  "timestamp": "2026-10-21T18:00:00.000Z",
  "data": {
    "call_id": "00000000-0000-4000-8000-000000000002",
    "phone_number": "+14155550100",
    "direction": "inbound",
    "agent_id": null
  },
  "cursor": null
}
```

The payload has no transcript, recording, summary, or status, because those may still be processing when the event fires. Call `get_call_log` with the `call_id` to fetch them. `phone_number` is `null` when the call record has no number for your side of the call.

### Delivery

- Deliveries are signed with HMAC-SHA256 following [Standard Webhooks](https://www.standardwebhooks.com). Verify the `webhook-id`, `webhook-timestamp`, and `webhook-signature` headers with your secret. The `X-MCP-Subscription-Id` header identifies the subscription.
- Any `2xx` response acknowledges the event. A `410` or `413` stops delivery of that event. Bland retries other responses and network failures with backoff for up to 24 hours.
- Delivery is at least once, so the same event can arrive more than once. Deduplicate on `eventId`.
- Webhook URLs must use HTTPS on a public address. Bland doesn't follow redirects. Respond within eight seconds.

## One endpoint, three MCP surfaces

Bland has three MCP-related surfaces. If you're unsure, use the first one.

| Surface | What it is | When to use it |
| --- | --- | --- |
| `https://api.bland.ai/v1/mcp` | **This server.** Remote, account-scoped, full toolset. | Building on Bland with an AI agent that signs in with Bland or already has an API key. |
| `bland mcp` ([CLI](/sdks/cli)) | A local stdio server bundled with the Bland CLI. | You prefer a local process, or your agent has no API key yet and needs to [onboard itself](/platform/connect-your-agent). |
| `https://docs.bland.ai/mcp` | The docs site's own MCP (search-only, no auth). | You only want documentation search. |

## Security notes

- Treat your API key like a password. Use environment variables or your client's secret storage. Never commit it to a repo.
- A sign-in connection acts as you, in the organization you chose, with the permissions of your role there. Review the consent screen before you approve, and disconnect apps you no longer use.
- OAuth tokens are only valid on `/v1/mcp`. They don't work on the REST API.
- Tools that spend money or touch live traffic (placing calls, publishing agents) are marked destructive so your client asks before running them. Review what your agent proposes before approving.
- MCP tool results can contain untrusted content (e.g. call transcripts of real conversations). Prompt-injection-aware clients like Claude Code treat tool output as data, but keep it in mind when building your own agent loops.
