The Bland MCP server lets any AI agent work with your Bland account through natural language: place and inspect calls, send texts, build and validate pathways, manage agents, query analytics, run evals, and search the Bland docs.

It's a remote [Model Context Protocol](https://modelcontextprotocol.io) server hosted by Bland. There's nothing to run locally: point your client at the endpoint, sign in with Bland or use your API key, and your agent has the full toolset.

```text
https://api.bland.ai/v1/mcp
```

## How it works

- **Transport:** Streamable HTTP (the current MCP standard). The server is stateless, so there are no sessions to manage and any request can hit any node.
- **Authentication:** [sign in with Bland](/integrations/mcp/oauth) (OAuth; ChatGPT, Claude, and Claude Code today, other clients once dynamic client registration is available), or your Bland API key in the `Authorization` header (`Bearer org_...`), which works with every client. Either way, one organization scopes every tool: an agent connected to your org sees only that org's calls, pathways, and agents. Get a key from the [dashboard](https://app.bland.ai/dashboard/settings), or let an agent obtain its own through the [Agent onboarding API](/platform/connect-your-agent).
- **Rate limits:** 120 requests per minute per organization.
- **Safety:** every tool is annotated read-only or destructive, so well-behaved clients ask before the agent does anything with side effects (like placing a real phone call). Mutating tools additionally require an explicit confirmation argument.

## Discovering the server from a 401

A request that reaches `/v1/mcp` with no credential gets a `401` that tells the client what to do next. Clients that already send a valid `Authorization` header never see it. Two pieces:

- A `WWW-Authenticate` header (RFC 6750):

  ```text
  WWW-Authenticate: Bearer realm="bland", resource_metadata="https://api.bland.ai/.well-known/oauth-protected-resource/v1/mcp", scope="mcp:read mcp:write"
  ```

  A credential that was refused gets `error="invalid_token"` on the same header.

- A JSON-RPC error body whose `error.message` and `error.data` name the header to send, where a human gets a key, and any self-serve signup flows an agent can run on its own: currently [headless onboarding](/platform/agent-headless-onboarding) and the [device-code flow](/platform/connect-your-agent). Each is listed only while it's enabled.

Which piece a client uses depends on what it supports:

- **OAuth clients** follow `resource_metadata` to the protected resource document (RFC 9728). It names the authorization server, `https://api.bland.ai/authorization`, and the scopes `mcp:read` and `mcp:write`. The authorization server's own metadata is at `https://api.bland.ai/.well-known/oauth-authorization-server/authorization` and `https://api.bland.ai/authorization/.well-known/openid-configuration`. From there the client runs the flow on [Sign in with Bland](/integrations/mcp/oauth). Clients that only register dynamically can't complete it yet and need an API key.
- **Agents with no key** read the body, pick a signup flow, obtain their own key, and retry the same MCP call.

## What your agent can do

| Category | Highlights |
| --- | --- |
| **Calls** | Place an outbound call (`create_call`), wait for it to finish (`wait_for_call`), stop it (`stop_call`), and fetch its transcript, recording, and summary (`get_call_log`). Pick a voice from Bland's curated set (`list_voices`). |
| **Pathways** | Compile-check a pathway graph before saving (`validate_pathway`), fetch the authoritative schema (`get_pathway_schema`), and get deep node/edge semantics (`get_pathway_context`). |
| **Agents** | Full lifecycle for the v2 agents model: create, version, branch, publish to staging, promote to production, manage environment variables. |
| **Analytics** | Structured call-analytics queries with grouping, filters, and time ranges (`query_analytics`). |
| **Evals** | List and inspect LLM judges, kick off eval runs over batches of calls. |
| **Docs** | Search and read docs.bland.ai from inside the session (`search_bland_docs`, `get_bland_doc`). |
| **Full API reach** | Anything not covered by a dedicated tool: `bland_api_get` for any GET endpoint, `call_bland_api` for any mutating endpoint. |

See the full [tool reference](/integrations/mcp/tools).

The server also ships MCP **prompts**: `build_pathway` and `edit_pathway` appear as slash commands in clients that support them (like Claude Code) and load Bland's pathway-authoring doctrine into the session.

## One endpoint, three MCP surfaces

Bland has three MCP-related surfaces. If you're unsure, use the first one.

| Surface | What it is | When to use it |
| --- | --- | --- |
| `https://api.bland.ai/v1/mcp` | **This server.** Remote, account-scoped, full toolset. | Building on Bland with an AI agent that signs in with Bland or already has an API key. |
| `bland mcp` ([CLI](/sdks/cli)) | A local stdio server bundled with the Bland CLI. | You prefer a local process, or your agent has no API key yet and needs to [onboard itself](/platform/connect-your-agent). |
| `https://docs.bland.ai/mcp` | The docs site's own MCP (search-only, no auth). | You only want documentation search. |

## Security notes

- Treat your API key like a password. Use environment variables or your client's secret storage. Never commit it to a repo.
- A sign-in connection acts as you, in the organization you chose, with the permissions of your role there. Review the consent screen before you approve, and disconnect apps you no longer use.
- OAuth tokens are only valid on `/v1/mcp`. They don't work on the REST API.
- Tools that spend money or touch live traffic (placing calls, publishing agents) are marked destructive and confirmation-gated, but review what your agent proposes before approving.
- MCP tool results can contain untrusted content (e.g. call transcripts of real conversations). Prompt-injection-aware clients like Claude Code treat tool output as data, but keep it in mind when building your own agent loops.
